# S2-5 設計: app の移し替えと世代

日付: 2026-11-23。設計のみ。実装・spec の変更・コミットは含まない。

## 1. 対象と判断

正は stage2 task 表の S2-5、stage2 spec 2・3・7・8章、core spec 10章、およびそれを置き換える multi-camera spec 7・9・10節とする。S2-5 は既存のコンソール動作を保って app に移し、世代の生成・停止・生成失敗を明示する。全 OS でコンソールを選ぶ。GUI、再起動操作、`POST /api/restart`、旧世代の秘密の蓄積は実装しない。

生成失敗時の内部状態とフロントの振る舞いを分ける。app は部分生成物を止めて `current == nil`、`apply.state == failed` とする。ここは将来の窓が待てる状態であり、HTTP は存在しない。S2-5 のコンソール実行はその状態を確認して理由を標準エラーに出し、直ちに 1 を返す。Windows も今は同じで、単独コンソールの Enter 待ちは維持する。GUI の失敗待機は後続 task、Linux の bak 復旧案内・端末判定・`--dir` は S2-7 とする。

task 表の未決事項 1 は、起動に必要な `apply` の最小部分だけ本設計で決める。7 は `InitJob` を先に移すため S2-5 にも関係し、失敗を記憶して最初の logger に警告を一度出す。12 は S2-6 の担当であり、今回は supervisor の API 資格情報を世代に持たせ、その世代の logger に API パスワードを追加するところまでとする。過去の秘密を保存する仕組みは作らない。

## 2. 型・関数と所有権

以下は実装時の形を示す宣言案であり、この文書ではコードを追加しない。

| 公開する形 | 契約 |
|---|---|
| `Options { BaseDir string; Stdout, Stderr io.Writer }` | 現在の `run` の引数を束ねる。基準フォルダと出力先は呼び出し側が指定する |
| `Run(ctx context.Context, opts Options) int` | コンソール用。App を一つ作り、プロセスの準備、最初の世代の作成、終了待ち、停止まで行う |
| `App` | 中身は非公開。世代の所有者。公開構築 API は今回は増やさず、将来 GUI 用の操作を追加できる構造にする |
| `Apply { State ApplyState; Kind ApplyKind; Reason string }` | 値のコピーで読み出す。`(*App).Apply() Apply` は mutex で保護。生成物のポインタは返さない |
| `ApplyState` | 今回は `idle` → `applying` → `applied` または片付け後に `failed`。Reason は失敗時のみ。通常終了で applied を failed にしない |
| `ApplyKind` | 今回の初回起動は空値。`live / restart / revert` は後続 task の予約で、初回に架空の `startup` を追加しない |

`generation` は非公開型とする（公開 `Generation` は不要）。`App.createGeneration(ctx) error` と `generation.stop()` も非公開。生成・停止を App の実行 goroutine で直列に行い、途中の generation は App.current に公開しない。段8を完了してから current に置く。stop は二重呼び出しでも一度だけ処理する。失敗理由はログと同じ秘密の置換規則で伏せ、設定検証の項目名と理由は保持する。

| 寿命 | 所有する型・内容 |
|---|---|
| プロセス | App: Options、終了要求 ctx、apply、InitJob の実行済みと失敗、最初の起動表示の印、成功時の設定ハッシュ、current |
| 将来のプロセス | App または OS フロントが所有する窓、mutex、crash 出力。セッション・使い捨て合言葉、秘密の集合、OBS URL 書換印は App に後で追加する。今回はダミー実装しない |
| 世代 | generation: 読んだ設定とハッシュ候補、logger（直近ログを含む）、supervisor と API 資格情報、Poller、samples、obs 本来・補助接続、MediaWatch、core と Machine、HTTP server/listener、serveErr、世代 cancel、開始済みの記録と WaitGroup |
| 将来の世代 | history の記録、SSE 配る役・接続、回線テスト「OBS にも反映」は generation に追加する |

設定ハッシュは段1で実際に読んだファイルのバイト列から SHA-256 を計算する。読み直して別版をハッシュしないよう、内部の設定ローダーが設定と同じ読み取りのバイト列（初回は生成して保存した内容）を返す。段8で App に確定し、失敗時は更新しない。bak は触らない。

`cmd/irl-live-keeper` に残るのは OS ごとのフロント選択、signal.NotifyContext、baseDir、os.Exit、console_*.go、pause.go と対応テスト。run/loadConfig/partsContext/hiddenPath、配線・URL・host・banner とそのテストは app に移す。main はコンソールの薄い呼び出し役とし、OS コンソール判定・Enter 待ちを app の世代に混ぜない。既存テスト用には app 内に旧引数の非公開 `run` ラッパーを置いてよいが、振る舞いの本体は一つにする。

## 3. 作る順

`InitJob` はこの表の外、App のプロセス準備で一回だけ呼ぶ。config が不正でも呼び出しは一回。失敗は生成失敗にしない。生成の各関数が返した資源は、次の処理の前に generation に所有させる。

| 段・記録名 | 処理・読むもの | 失敗と片付け |
|---|---|---|
| 1 `config.load` | config.yaml を読む・検証する。ないときだけ生成する。パス解決、ハッシュ候補を得る | 読取・構文・検証・生成失敗は config の失敗。稼働部品なし |
| 2 `logger.open` | 当世代の秘密で logger を開き、config.Warnings を記録。保存した InitJob 警告を一回出す | open 失敗では稼働部品なし。open 内の部分ファイルは open 側で閉じる |
| 3 `ports.check` | supervisor.CheckPorts。無効な受付のポートは調べない | logger のみ存在。logger を閉じる |
| 4 `banner.write` | host とカメラ URL を決め、従来の表示を stdout に直接一回書く | 現在同様 Writer のエラーは新しい生成失敗に数えない |
| 5 `process.configure` | プロセス所有物への設定引き渡し位置。今回は空の段 | セッション失効・窓への設定は将来追加 |
| 6 `parts.create` ～ `parts.start` | supervisor → API 資格情報 → Poller → obs・MediaWatch → hidden 読取 → core。全受け手登録後に各 Run を開始 | OBS 接続不良や supervisor の再試行は生成失敗にしない |
| 7 `http.listen` → `http.serve` | net.Listen を同期的に呼び、成功した listener を所有して Serve を開始 | Listen 失敗は稼働部品一式を停止し logger を閉じる |
| 8 `config.commit` | 読んだ版のハッシュを App に記憶し、current と applied を確定 | 新しい I/O はしない。段7より前に成功扱いしない |

段6の詳細は次の順に固定する。

1. supervisor を新規作成して APICredentials を取得し、API パスワードを logger.AddSecrets に追加する。Poller に同じ資格情報を渡す。samples は現行どおり容量0。
2. obs、MediaWatch を作る。`core.LoadHidden(hiddenPath(BaseDir))` を core.New の前に行う。hidden は `state/hidden.json`。警告と読み込んだ件数のログを保つ。読めない場合は空、壊れたファイルは .broken に退避する既存処理を使い、生成失敗にしない。
3. deps の HiddenPath/HiddenRestored/HiddenLoadWarning、Machine、OBS、MediaMTX 状態、SlowReaders、Warnings、MediaWatch、Log、カメラ設定を現行配線どおり渡して core.New。空の地図では hidden 記録を残し、接続先・コレクション等の照合は既存 core に任せる。
4. `receivers.register` の位置で history、web の配る役、app の受け手をすべて登録する。今回は実際の受け手がないため空。使わない購読・捨てるだけの goroutine は作らない。後続 task ではこの段に SubscribeEvents(n)/SubscribeSnapshots を差し込む。
5. `parts.start` で supervisor、Poller、obs、core、MediaWatch 終了役を開始し、それぞれの開始を記録する。呼び出しを発行する順はこの列だが、goroutine の実際の実行順は保証しない。登録完了はすべての Run の開始より前。将来の Snapshot 受け手は開始時に Snapshot を一回読み、その後は知らせで読む。Run 後の登録は禁止、容量の値は担当 task で決める。

### 生成失敗の四経路

各失敗で片付けを完了してから `current=nil; apply={failed, 空kind, 伏せた理由}` を確定する。logger があれば理由を閉じる前に記録する。コンソールは stderr に現行の理由を出し 1 を返す。失敗段の情報は内部エラーに保持する。

| 失敗 | その時点で動いているもの | 片付けの列（存在しない段はスキップ） |
|---|---|---|
| config 読取・不正 | なし。InitJob だけはプロセス準備済み | 資源停止なし → failed |
| logger open | なし | open 自身の部分資源解放 → failed |
| ポート事前確認 | logger。子プロセスなし | logger.close → failed |
| 管理 API Listen | logger、supervisor/MediaMTX、Poller、obs、core、MediaWatch。HTTP Serve は未開始 | Stopping → SSE 空 → HTTP 空 → cancel → 全部品待ち（子の回収を含む）→ history 空 → logger.close → failed |

Listen の偽失敗は MediaMTX の開始を同期障壁で確認してから返す試験を必須とする。実運用では supervisor の開始前に Listen が失敗する可能性もあり、どちらでも開始済みの Run を待つ。Listen が返した資源は失敗時も adapter が漏らさない。通常の Serve が後から予期せず終了した場合は生成失敗ではなく実行時エラーで、同じ停止処理を通って終了コード1。ErrServerClosed を通常停止のエラーにしない。

生成直後に段2/3で失敗したときは管理パスワードの行を stdout に一回だけ出す。段4以後の失敗では表示済みなので重ねない。既存 config なら出さない。初回生成ファイルを失敗の後始末で削除しない。

## 4. 止める順

`Stopping` は「段3の前」を満たす位置のうち、**段1の前**に置く。これにより現在の shutdown の `Stopping → HTTP → cancel → Wait` をそのまま保つ。SSE の停止を足しても、HTTP が長引く前に復元を始められる。

| 段・記録名 | 処理 | 現行との対応・追加位置 |
|---|---|---|
| 前段 `core.stopping` | core.Run 開始済みなら独立の終了 ctx（上限 core.DefaultStopTimeout=2秒）で Stopping。RestoreAll の応答完了・hidden 保存、または期限で戻る。2秒を必ず寝て待つ意味ではない | 現行 shutdown の最初。プロセス ctx の取消しを伝えない |
| 1 `sse.close` | 今は空 | S2-11: 全 SSE 接続を閉じる。停止時に新規接続も増えない仕組みを差し込む |
| 2 `http.shutdown` | 存在すれば Shutdown。独立の ctx で現行の上限1秒。失敗は Close で強制終了 | 現行の二番目。Serve の終了も回収する |
| 3 `generation.cancel` | 世代 cancel を一度呼ぶ | 現行 cancel |
| 4 `parts.wait` | 全開始済み Run と MediaWatch 終了役、Serve の終了を待つ。core.Run の return まで待つ | 現行 wg.Wait を含む。MediaMTX の終了と Wait を省略しない |
| 5 `history.finish` | 今は空 | S2-37: core の購読を閉じるまで読み切り、最後の Dropped を読み、interrupted の end/summary を書く。history は世代 ctx で先に止めない |
| 6 `logger.close` | 終了ログを書いて logger を閉じる | 現行 defer logger.Close。すべてのログ生産役の回収後 |

作りかけにも同じ停止関数を使うが、開始・所有済みの段だけ実行する。Run を呼んでいない core には Stopping を呼ばず、閉じない購読チャネルを待たない。登録だけした将来の受け手も未開始なら破棄する。部分生成の途中で生成関数が資源を取得して失敗する場合は、その関数が資源を解放してから返す。

supervisor の stop（interrupt、grace 後 kill、子の Wait）と exitSettle は変更しない。Windows のコンソールを閉じたとき MediaMTX が先に終わっても、現行の exitSettle の待ちと「本体の終了と同時」の扱いを保つ。世代停止に別の短い全体タイムアウトを付けて子の回収を打ち切らない。

## 5. ctx・goroutine・チャネル

| 対象 | ctx / チャネル | 終了・待つ責任 |
|---|---|---|
| App の実行役 | 呼び出し元のプロセス ctx。シグナルは停止開始の合図 | cmd が Run の return を待って os.Exit |
| generation | `WithCancel(WithoutCancel(processCtx))`。値は引継ぎ、親の取消し・期限は引き継がない | App が停止段3だけで cancel |
| supervisor / Poller / obs / core.Run | 世代 ctx。samples は容量0 | generation の WaitGroup。Poller の送信も ctx で抜ける既存実装を維持 |
| core 内の実行役・保存役・media 配る役 | 世代 ctx。既存 core の列・承認・応答チャネル | core.Run が内部の待ちを済ませる。app は二重管理しない |
| MediaWatch 終了役 | 世代 ctx の Done で Close | generation が終了役を WaitGroup で待つ |
| HTTP Serve | listener の Close/Shutdown で終了。`serveErr` は容量1 | 最初のエラー受信後でも二重受信を待たないよう別の serveDone（close のみ）を持ち、段4で回収 |
| HTTP 要求 | net/http の要求 ctx、現行 web の commandTimeout | Shutdown 上限後は Close。停止処理の ctx に要求 ctx を流用しない |
| Stopping / HTTP Shutdown | 親の取消しと独立した timeout ctx、2秒 / 1秒 | 停止関数が呼出しから return まで待つ |
| 購読（将来） | Snapshot は容量1、Event は受け手が決定 | 登録は段6、close は core.Run。history は close 後 Dropped を読む |
| history（将来） | 世代 cancel から独立した drain 用の寿命 | 段5で app が終了を待つ。S2-5 では作らない |

停止後に残ってはいけないのは App が起こした Run、HTTP Serve、タイマー、MediaWatch、Poller、MediaMTX の子・Wait 未回収、登録だけした受け手の待ち。現状の goobs 内部 goroutine の停止不能という既知の制約は拡大しない。core.callOBS は ctx を受けない OBS 呼出しを別 goroutine にし、取消し後は容量1の結果へ返して終了する。この「応答待ちの呼出し」と goobs の既知の残存は app の WaitGroup に追加せず、世代・新しい core に遅い結果を配送しない。終了待ちを無制限に伸ばさない。

## 6. テストと偽の差し込み口

app と同じパッケージのテストで、非公開 `newApp(opts, deps)` の deps を差し替える。公開 Options にテスト専用フィールドを増やさない。deps は LoadConfig/Generate、OpenLogger、CheckPorts、InitJob、NewSupervisor、NewPoller、NewOBS、LoadHidden、NewCore、NewMediaWatch、Listen、NewHTTP の関数フィールドを持つ。デフォルトは既存実装に委譲する。

戻り値の最小 interface は `runner{Run(context.Context)}`、`pollRunner{Run(context.Context,time.Duration,chan<- ingest.SampleSet)}`、`logHandle{Slog() *slog.Logger; AddSecrets(...string); Close() error}`、`httpServer{Serve(net.Listener) error; Shutdown(context.Context) error; Close() error}`、`stopper{Stopping(context.Context)}`、`closer{Close()}` を基礎にする。supervisor adapter は Status/SlowReaders/APICredentials、core adapter は web.Backend と Run/Stopping/購読を公開し、OBS adapter は core が要求する既存 interface と Warnings/Aux の配線を満たす。具体型しか返さない既存 constructor を直接偽にするためだけに他パッケージの公開 API を変更せず、app 内で包む。SSE/history 用の汎用 plugin 機構は作らない。

偽は mutex 付き recorder と開始・終了の明示チャネルを持つ。Run 呼出しを起こす側の記録と、実際に開始した側の合図を区別し、sleep による順序試験はしない。空の段は段を呼ぶ app 側の recorder で記録する（製品ログには出さない）。

| 試験 | 期待値 |
|---|---|
| 成功時の生成順 | `config.load, logger.open, ports.check, banner.write, process.configure, parts.create, hidden.load, core.new, receivers.register, parts.start, http.listen, http.serve, config.commit`。hidden.load は core.new より前、全購読は core.Run より前 |
| 成功時の停止順 | `core.stopping, sse.close, http.shutdown, generation.cancel, parts.wait, history.finish, logger.close`。部品の return 同士の順は固定せず、すべてが parts.wait 完了より前 |
| InitJob | App の準備で1回、世代の上記二列には0回。警告は logger.open 後の1回だけ。偽失敗でも世代は applied |
| config の失敗 | 読めない・YAML 不正・検証違反を表で試す。`config.load, apply.failed` のみ。current nil、理由あり、console=1 |
| logger の失敗 | `config.load, logger.open, apply.failed`。部品 Run/Close は0、生成時のみパスワード1回 |
| ポートの失敗 | `config.load, logger.open, ports.check, logger.close, apply.failed`。MediaMTX は未開始、banner は0、console=1 |
| Listen の失敗 | 成功列の http.listen まで（http.serve/config.commit なし）→ `core.stopping, sse.close, generation.cancel, parts.wait, history.finish, logger.close, apply.failed`。実 HTTP はないので http.shutdown は記録しない。開始済み偽 MediaMTX の stop/Wait 完了を確認、全 Run が return、current nil、ハッシュ未確定 |
| Stopping の猶予 | 偽が応答するまで世代 ctx は有効、期限は約2秒。即応なら即座に次へ。応答しなくても期限で cancel へ進む。RestoreAll/hidden 保存の実際の照合は既存 core 試験を維持 |
| HTTP 停止の失敗 | Shutdown に1秒の期限、失敗時は Close、その後 cancel/wait/close。Serve が先に戻っても終了待ちが詰まらない |
| 劣化運転 | OBS 未接続・MediaMTX 再試行中でも Listen 成功なら applied、console はシグナルまで継続 |
| 初回の生成 | 実ローダー＋一時フォルダで config.yaml を作り、生成物の検証成功、パスワード行と URL が一回、ログでは秘密が ***。二度目は生成しない |
| hidden | 正常・不在・壊れた記録。既存の HiddenRestored 等へ同じ値、警告、.broken、空の地図の保持。読取失敗で apply.failed にしない |
| プロセス ctx | 親 cancel だけでは部品 ctx は有効。停止手順で取り消す。ctx の値は保持 |

段名列の試験用 recorder は deps の関数・偽のメソッドと非公開の段通知関数で実現する。段通知の本番既定は何もしない関数。段の通知だけで判定せず、偽の実 Run が止まり子が回収されたことを別途確認する。

既存 main_test.go、main_linux_test.go、wiring_test.go、banner_test.go、host_test.go、genpass_test.go は app に移し、期待値は変えない。generate の差し替えは互換ラッパーまたは deps へ移す。shutdown/partsContext/hiddenPath の試験も移す。pause_test.go は cmd に残す。特に秘密のログ置換、生成後ログ・ポート失敗時の表示、カメラ順と無効なプロトコル、管理 API の待受アドレス、Linux で終了直後の子 PID が ESRCH であることを維持する。コンソール閉鎖と Ctrl+C の Windows 実機確認は従来の受入確認として残す。

## 7. 実装を三回に分ける案

| 回 | 渡す受入条件（各回2〜3件） |
|---|---|
| 1: 移し替え | ① run・配線・表示・host と関連テストを app に移して挙動を維持。② cmd を OS フロント選択と既存のシグナル・終了コード・Enter 待ちに絞る。③ InitJob を App 準備へ移し一回だけ呼び、失敗は logger 開始後に警告 |
| 2: 世代 | ① generation と作成1〜8、停止前段＋1〜6を実装し、段5/history/SSE の空の位置を確保。② hidden の段6読取と購読登録-before-Run、ctx 分離・全開始済み処理の回収を検証。③ 読んだ版のハッシュの段8確定と apply の最小遷移を実装 |
| 3: 失敗 | ① 四経路で failed/current nil と部分資源回収を偽で検証（起動済み MediaMTX を含む）。② 初回生成・失敗時表示・終了コードと既存回帰試験を維持。③ Serve 異常終了・HTTP 強制 Close・Stopping 期限の試験で終了経路を閉じる |

各回の終わりで `go test -race ./...`、`go vet ./...`、`GOOS=windows go vet ./...` を実行し全て緑とする。今回の設計作業ではサービス起動やテスト実行は行わない。再起動の公開関数や409、旧秘密の継承テストは S2-6 に渡す。

## 8. spec に足す文の案

実装前に担当者が以下を spec と変更履歴へ追記する。本作業では spec 自体は変更しない。

- 「初回起動の apply は idle から applying へ進み、世代の段8の成功で applied、部分生成物の停止後に failed と理由になる。初回の kind は空とし、live/restart/revert は該当する操作にだけ使う。通常終了は反映失敗ではない。」
- 「世代作成の内部処理は、失敗時に世代を持たず apply を保持して戻る。コンソールの呼び出し側は理由を表示して終了コード1を返す。GUI の待機は GUI 実装時に追加する。S2-5 の間は全 OS で既存のコンソール動作を保つ。」
- 「Stopping と最大2秒の待ちは止める順の1の前に行う。世代 ctx はシグナルの取消しから独立させ、Stopping と HTTP 停止の後で取り消す。HTTP Shutdown の猶予は1秒、失敗時は Close する。」
- 「InitJob の失敗はプロセスに記憶し、最初に logger を開けたときに一度だけ警告として書く。世代作成の失敗にはしない。」
- 「成功版のハッシュは段1で設定として読んだ同一バイト列から作り、段8で確定する。作成失敗時は成功版を更新しない。bak は世代作成では更新しない。」
- 「Run を開始していない core の停止では購読チャネルの close を待たない。開始済みの部品は同じ世代停止手順で回収し、MediaMTX の終了・Wait が済む前に logger を閉じない。」

S2-6 への引き継ぎ: 同じ createGeneration/stop を直列に呼ぶ再起動、applying 中の排他と409、プロセスの秘密集合（MediaMTX API パスワードを含む）、初回だけの表示、セッション寿命を追加する。S2-5 の段を再実装せず、この所有権と順序を使う。
