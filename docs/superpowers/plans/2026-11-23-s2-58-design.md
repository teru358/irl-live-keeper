# S2-58 設計（レビュー修正）

補助接続の SetCurrentProgramScene を送る前に、中核ループへ UUID・要求ID・期限を持つ人の意図を登録する。要求は呼び出し側の goroutine で待ち、中核ループを止めない。期限は登録時から7秒（補助接続の2秒と余裕5秒）。一覧確認は登録前に行う。

要求の成功は到着を意味しない。現在のシーンは SceneChanged でだけ更新する。意図と一致する通知は本体の期待より優先して人の切替として releaseAll を適用し、期待・スタック・持ち主・manual の戻り先を解除する。項目の処理は既存の人の切替と同じ refine / jb を通る。Studio Mode の通知も obs 層の既存の250ms保留を通す。

意図のある間は AutoFail・AutoRecover・StartScene を新しく送らず、既存バッチも送信直前の承認で却下する。登録時点で同じシーンなら、その場で人の切替として解除し、OBS への要求は省く。

意図は要求IDごとに独立して保持し、取消は同じIDだけを消す。同じシーンの選択も他の要求の意図を消さない。UUIDごとの有効期限は残る要求の最も遅い期限となる。SceneChanged(U) はUの意図が一つでもあれば人の切替として扱い、Uの意図をすべて消す。他UUIDの意図は残す。

OBS の要求結果statusの失敗だけを明確な拒否として意図を取り消し502。補助接続がないなど未送信が確実な場合も同じIDを取り消し503。期限切れ・応答ID不一致・送信後の切断・その他の通信エラーは適用の有無が不明なので意図を期限まで残し503。成功後も通知か期限まで意図を残す。本体の切断通知でも意図は消さない。期限後は通常の期待照合規則に戻る。goobs v1.11.1 が失敗statusから作る文字列は要求名・status名・codeの一致を検査し、専用エラーに分類する。

画面は接続時、現在の UUID が一覧にない場合、接続中の10秒ごとに一覧を取り直す。同時取得を抑え、取り直しでも送信中の印を保つ。

## spec 追記案

屋外からのシーン選択は補助接続へ要求する前に、要求ID・UUID・7秒の期限を持つ人の意図を登録する。意図は要求ごとに保持し、取消は同じ要求IDだけに適用する。UUIDごとの期限は残っている意図の最も遅い期限とする。要求の成功では現在シーンを変えず、SceneChanged(U)で確定する。Uの有効な意図があれば本体の期待より優先して人の切替として扱い、Uの意図をすべて消す。他UUIDの意図は残す。意図が一つでもある間はAutoFail・AutoRecover・StartSceneを新しく送らず、作成済みバッチも送信直前の承認で却下する。OBSの要求結果statusの失敗は同じIDの意図を取り消して502、補助接続がないなど未送信が確実な場合は同じIDを取り消して503とする。期限切れ・応答ID不一致・送信後の切断など適用不明のエラーは意図を期限まで保持して503とする。切断通知だけでは意図を消さない。同じシーンの選択は登録時に人の操作として確定し、他要求の意図を保持したままOBSへの要求を省く。人の切替は期待・スタック・所有権・manualの戻り先を解除し、隠した項目は既存の人の切替と同じrefine / jbで処理する。Studio Modeでもprogramを変更し、F-9の通知保留を通す。
