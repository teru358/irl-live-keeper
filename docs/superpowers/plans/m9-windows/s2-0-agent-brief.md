# S2-0 spike の代理の確認（小さな窓・Job の外で開く・CLI・ダークモード・アイコン。Windows の Claude Code 向けの指示書）

あなたは、irl-live-keeper（以下「本体」）の第2段階で作る「小さな窓」の前に、Windows の実機で試しの exe を動かして確かめる。この指示書のフォルダ（`s2-0`。以下「試しのフォルダ」）で作業する。**ユーザーへの文は日本語で書く。** 目で見て判断すること（窓の見た目、ブラウザが残ったか）はユーザーに頼み、それ以外（起動、ログの読み取り、プロセスの確認、記録）はあなたが行う。

## 試しのフォルダの中身

- `spike.exe`: 試しの窓（GUI の版。コンソールの窓を出さない）。引数 `--cli-alloc`、`--cli-attach`、`--theme` で動きが変わる
- `spike-console.exe`: 同じものの、コンソールの版（比べるため）
- `A2.ico`、`C2.ico`、`icons-preview2.png`: アイコンの案（exe には組み込んでいない）
- 動かすと、同じフォルダに `spike-log.txt` が足されていく（時刻つき）

## 守ること

- 本体（`irl-live-keeper.exe`）、OBS、MediaMTX には触れない。この試しはポートを使わない
- `spike.exe` は、起動すると子として `ping -t 127.0.0.1`（窓なし）を起動する（本番の MediaMTX の代わり）。**止めてよいプロセスは、spike が起動したもの（`spike-log.txt` に PID が出る）と spike 自身だけ。PID で止める。** `Stop-Process -Name` は使わない
- Windows の設定（ダークモードなど）は、あなたは変えない。ユーザーに頼む
- ブラウザを閉じてもらうときは、ユーザーの作業を壊さないよう、閉じてよいか先に聞く
- 迷ったら、進めずにユーザーに聞く

## 確かめること

各項目のあとに `spike-log.txt` の新しい行を記録に写す。

| # | 手順 | 記録すること |
|---|---|---|
| W-1 窓（ライト） | Windows がライトモードのときに、ユーザーに `spike.exe` をダブルクリックで起動してもらう（あなたが `Start-Process .\spike.exe` で起動してもよい） | ユーザーに見てもらう: 窓が開くか、コンソールの窓が出ないか、状態の行（カメラ3台、OBS、待機、MediaMTX）の並び、文字が1秒ごとに変わり色（緑・黄・赤）が変わるか、ボタンの見た目（古い Windows の形か、今の形か）、文字のにじみ・切れ、題名の帯。ログの Job と ping の行 |
| W-2 Job の外で開く（ブラウザが動いているとき） | ユーザーの既定のブラウザが開いている状態で、窓の「ブラウザ A」（Job の外で開く）と「ブラウザ B」（ふつうに開く）と「フォルダ」を押してもらう | どちらも example.com が開いたか、エクスプローラーが開いたか。ログの各行（成功・失敗、PID） |
| W-3 終了 | 窓の「終了」を押し、確認で「はい」 | ユーザーに見てもらう: ブラウザのタブ（A と B）とエクスプローラーが残ったか。あなたは `Get-Process -Id <ping の PID>` で ping が消えたか |
| W-4 Job の外で開く（ブラウザが動いていないとき） | ユーザーに、既定のブラウザをすべて閉じてよいか聞き、よければ閉じてもらう。`spike.exe` を起動し、「ブラウザ A」を押す → 開いたら「終了」→「はい」。もう一度 `spike.exe` を起動し、「ブラウザ B」で同じく | どちらの方法で開いたブラウザが、spike の終了のあとも残ったか（ここがいちばん大事。Job の中で起動されたブラウザは、本体の終了で一緒に閉じることがある） |
| W-5 窓（ダーク） | ユーザーに、Windows の設定 → 個人用設定 → 色 →「既定のアプリ モードを選択します」を「ダーク」にしてもらう（あとで戻すかはユーザーに任せる）。`.\spike.exe --theme` を動かし、ログの値を見る。`spike.exe` を起動してもらう | ログの `AppsUseLightTheme` の値。ユーザーに見てもらう: 題名の帯が暗いか、窓の地と文字が暗いか、ボタンが明るいまま浮いて見えるか、読みやすいか。案内の欄の DWM の結果 |
| W-6 CLI（自分のコンソール） | PowerShell から `.\spike.exe --cli-alloc` | 新しいコンソールの窓が開いたか、1秒ごとの行が10行出たか、途中で Ctrl+C を押すと「止める操作を受けました」で終わるか（ユーザーに押してもらう）。元の PowerShell のプロンプトがすぐ戻ったか |
| W-7 CLI（起動した端末） | PowerShell から `.\spike.exe --cli-attach`。cmd.exe からも同じく | 同じ PowerShell に行が出たか、プロンプトと混ざったか（出力の途中でプロンプトが出てしまうか）、Ctrl+C が効いたか。cmd.exe との違い |
| W-8 コンソールの版 | PowerShell から `.\spike-console.exe` を起動（引数なし。窓が出る） | 窓といっしょに、コンソールの窓が出るか（比べるため）。終了で両方閉じるか |
| W-9 アイコン | ユーザーに、試しのフォルダをエクスプローラーで「大アイコン」と「詳細」の表示にして、`A2.ico` と `C2.ico` を見てもらう。`icons-preview2.png` も見てもらう | どちらが好みか、小さいとき（詳細の表示）に見分けられるか、ほかの案が欲しいか |

## 片づけ

- spike の窓がすべて閉じていること。`Get-Process spike, spike-console -ErrorAction SilentlyContinue` が空
- ログに出た ping の PID がすべて消えていること（残っていれば、その PID だけを止める）
- ダークモードを戻すかはユーザーに聞く

## 記録

試しのフォルダに `s2-0-result.md` を作り、項目ごとに、ユーザーの言葉と、ログの行と、あなたの判断（合格 / 不合格 / 気になる点）を書く。最後に、次の4つについての意見を書く:

1. windigo の窓で、本番の小さな窓（spec の図）を作れそうか（見た目の問題、ダークでの見え方）
2. ブラウザとフォルダを開く方法は A（Job の外）でよいか
3. CLI は `--cli-alloc` と `--cli-attach` のどちらがよいか（プロンプトとの混ざり方、Ctrl+C）
4. アイコンはどちらの案か

最後に `spike-log.txt` の全文を `s2-0-result.md` の末尾に貼る。ユーザーに、`s2-0-result.md` ができたことを伝える。
