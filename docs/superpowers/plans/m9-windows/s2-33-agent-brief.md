# S2-33 区切り2の実機の確認（設定の画面と保存・反映。Windows の Claude Code 向けの指示書）

あなたは、irl-live-keeper（以下「本体」）の第2段階・区切り2の実機の確認を、ユーザーと一緒に進める。この指示書のフォルダ（`s2-33`。以下「確認のフォルダ」）で作業する。**ユーザーへの文は日本語で書く。**

## 前提・守ること（今までと同じ）

- パスワードを画面への出力・記録・ユーザーへの文に書かない。`config.yaml` と `ws-password.txt` を表示しない。**あなたは config.yaml を書き換えない**（設定の変更は、ユーザーが管理ページの設定の画面か、エディタで行う）
- 止めてよいプロセスは、あなたが起動したものだけ（PID で）。本体と OBS はユーザーが起動・終了する。シーンコレクションを切り替えない
- ログは `logs\` の今日のファイル。項目ごとに、新しい行を読んで記録する
- 迷ったら、進めずにユーザーに聞く

## 始める前に

1. ユーザーに本体を終了してもらう
2. あなたが、本体のフォルダの `config.yaml` を `config.yaml.before-s2-33` という名前で写す（中身は表示しない。`Copy-Item` で）。終わったあと元に戻すかはユーザーが決める
3. ユーザーに、確認のフォルダの `irl-live-keeper.exe` を、本体のフォルダの exe と入れ替えてもらう（元の exe は別の名前で残す）

## 新しくできたもの（今の版にあるものだけ）

- 管理ページのメニュー（PC は上の並び、スマホは右上の ≡）に「設定」。区分ごとに項目が並び、項目ごとに「すぐ反映」か「再起動して反映」の印がある
- 設定の画面の下に「保存」「読み直す」「直前の保存を取り消す」「本体を再起動する」と、3つのパスワードの「作り直す」（管理・送信用・読み取り）
- 「保存」などを押すと「変更の確認」が開き、変わる項目と反映の仕方が出る。「反映する」で実行。OBS 用の URL が変わるときだけ「OBS のメディアソースも書き換える」の選択が出る
- 窓: 起動や再起動に失敗し、前の版（`config.yaml.bak`）があり中身が違うときだけ「元に戻して再起動」
- 新しく作る config.yaml では管理ページのパスワードが空。同じ PC のブラウザから「パスワードを決める」画面で決める（下の T-13）

**まだないもの**: 配信の記録（履歴）の画面は区切り3。確認の文に「記録中の配信は…」と出ても、記録はまだない（文言はあとで直す）。

## 確かめること

| # | 手順 | 確かめること |
|---|---|---|
| T-1 設定の画面 | 本体を起動し、窓の「管理ページを開く」→ メニューの「設定」。PC とスマホ（LAN か Tailscale）で見てもらう | 区分が並び、項目に値と「すぐ反映 / 再起動して反映」の印。パスワードの欄は伏せてあり「表示」で見える（見るのはユーザーだけ。あなたは記録しない）。スマホでは1列。ライトとダーク。感想と、気になる文言はメモだけ |
| T-2 すぐ反映 | 設定の画面で、閾値（例: `switch` の `low_sec`）を1つ変えて「保存」→「変更の確認」→「反映する」 | 確認に「すぐ反映」と出ること。本体が再起動しないこと（窓の回線の行が途切れない。ログに `restart requested` が出ない）。「読み直す」で新しい値。エディタで config.yaml を開いてもらい、その1行だけが変わり、コメントと並びが残っていること（ユーザーに見てもらう。値はあなたに伝えなくてよい） |
| T-3 再起動して反映 | `mediamtx` の `rtmp_port` を、空いている番号（例: 19350）に変えて保存 | 確認に「再起動して反映」と出ること。ログに `restart requested`、`generation stopped`、`restart complete`。管理ページの状態が戻ること。窓の案内に再起動中の文が出たか（ユーザーの言葉） |
| T-4 ポートの確かめ | あなたが `powershell -ExecutionPolicy Bypass -File .\occupy-ports.ps1 -Target rtmp -Rtmp 19351` を裏で起動（PID を控える）。ユーザーに `rtmp_port` を 19351 にして保存してもらう | 保存が断られ、`rtmp_port` の欄の下に理由が出ること。config.yaml が変わっていないこと（ユーザーに見てもらう）。スクリプトは PID で止める |
| T-5 直前の保存を取り消す | 「直前の保存を取り消す」→「反映する」 | T-3 の変更が戻ること（`rtmp_port` が元の番号に。再起動して反映）。もう一度押すと、T-3 の値にまた戻ること |
| T-6 本体を再起動する | 「本体を再起動する」→「反映する」 | ログに `restart requested` と `restart complete`。状態が戻ること |
| T-7 元に戻して再起動 | (1) あなたが `powershell -ExecutionPolicy Bypass -File .\occupy-ports.ps1 -Target rtmp -Rtmp 19352` を裏で起動する（19352 は本体が使っていない番号。PID を控える）。T-5 までで一度は設定の画面から保存していること（`config.yaml.bak` ができている）。(2) ユーザーにエディタで config.yaml の `rtmp_port` を 19352 に書き換えて保存してもらう。(3) 管理ページの「本体を再起動する」 | 再起動に失敗して、窓に失敗の理由と「元に戻して再起動」が出ること。管理ページは開けなくなる（それでよい）。「元に戻して再起動」→ 本体が動き出すこと。ログに `restore backup requested` と `restart complete`。スクリプトは PID で止める |
| T-8 LAN から開く | 設定の画面で `admin` の `lan` をオンにして保存（再起動して反映）。スマホ（家の Wi-Fi）で `http://<PC の LAN のアドレス>:<admin.port>/` を開いてログイン → 設定 | オンにするときに LAN の注意の文が出ること。スマホで、`mediamtx` の `binary` と `log` の `dir` が表示だけ（変えられない）で、同じ PC からだけ変えられる旨の文が出ること。スマホから閾値を1つ変えて保存できること |
| T-9 管理ページのポート | PC の設定の画面で `admin` の `port` を空いている番号（例: 18787）に変えて保存 | 保存のあと、新しいポートの管理ページへ移ること（ログインし直しになる場合はその旨）。窓の「管理ページを開く」も新しいポートで開くこと。終わったら 8787 に戻す |
| T-10 パスワードの作り直し（管理） | 「管理パスワードを作り直す」→「反映する」 | 今の PC のブラウザはログインしたまま。スマホなど、ほかで開いていたページはログインし直しになること。新しいパスワードは設定の画面の「表示」で見える（ユーザーだけ） |
| T-11 パスワードの作り直し（読み取り）と OBS のメディアソース | OBS を起動しておく。「読み取りパスワードを作り直す」→ 確認で「OBS のメディアソースも書き換える」にチェック →「反映する」 | 再起動して反映。OBS のメディアソースのプロパティの URL が新しくなっていること（ユーザーが見る。URL は伝えなくてよい）。カメラから送っていれば、映像が戻ること。ログと管理ページの警告に URL やパスワードが出ないこと |
| T-12 配信中の確認（任意） | 試験の配信先を使ってよいときだけ。OBS で配信を始め、再起動して反映の項目を変えて「保存」 | 「変更の確認」が赤く、配信が切れる注意が出ること。「キャンセル」で何も変わらないこと。配信を止める |
| T-13 初回のパスワードを決める | 本体を終了してもらう。あなたが確認のフォルダに `first-run` という空のフォルダを作り、exe を写す。ユーザーにその exe を起動してもらう（OBS がつながらない警告は出てよい） | 窓の案内に、管理ページを開いてパスワードを決める旨が出ること。「管理ページを開く」→「パスワードを決める」画面（8文字以上を2回、表示のボタン）。決めると、そのまま管理ページに入れること。`first-run\config.yaml` の `admin.password` が埋まり、コメントが残っていること（ユーザーに見てもらう）。スマホから `first-run` の本体の管理ページは開けないこと（`admin.lan` は既定で false なので、つながらなくてよい）。終わったらユーザーに終了してもらい、`first-run` フォルダは消してよいかユーザーに聞く |

## 片づけ

- あなたが起動した `occupy-ports.ps1` を PID で止める
- `admin.lan`、`admin.port`、`rtmp_port` などを元に戻すか、`config.yaml.before-s2-33` に戻すかはユーザーに聞く（戻すのはユーザー）
- 本体は、ユーザーの判断で動かしたままにするか、終了してもらう

## 記録

確認のフォルダに `s2-33-result.md` を作り、項目ごとに、ユーザーの言葉、ログの行（パスワードと URL を除く）、あなたの判断（合格 / 不合格 / 気になる点）を書く。最後に、気になった文言と見た目の一覧をまとめる。**指示書の誤り（書いてあるボタンや画面が見つからない、手順が合わない）も、別の見出しで書く。** ユーザーに、できたことを伝える。
