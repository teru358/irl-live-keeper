# S2-33 の確かめ直しと、見た目の直しの確認（chrome-devtools-mcp を使う版。Windows の Claude Code 向けの指示書）

前回（`../s2-33/s2-33-agent-brief.md` と `../s2-33-result.md`）の続き。**前提・守ることは前回の指示書のとおり**（パスワードと URL を書かない、config.yaml と ws-password.txt を表示しない、**あなたは config.yaml を直接書き換えない**、止めてよいのは自分が起動したものだけ〔PID で〕、本体と OBS はユーザーが起動・終了する）。ユーザーへの文は日本語。

**今回は、管理ページの確かめを、あなたが chrome-devtools-mcp で行う。** ユーザーにお願いするのは、devtools で見られない所（窓、スマホ、配信、最初のログイン）だけ。手順は画面に出る名前で書いてある（「」の中が画面の文字）。前提の状態（「LAN から開く」がオンかなど）は決めつけず、今の値を見てから進める。

## devtools で守ること（パスワードと合言葉）

- **管理ページの操作（設定の変更と「保存」「反映する」を含む）は、あなたが devtools で行ってよい**（2026-11-25 のユーザーの許可）。config.yaml を直接書き換えるのは引き続きしない
- **「表示」のボタンを押さない**（パスワードが見える）。パスワードの欄に文字を入れない
- **「送信の設定」の画面は、写し（take_screenshot）も中身の読み取り（take_snapshot、evaluate_script での本文の読み取り）もしない**（URL とパスワードが文字で出る）。この画面の確かめはユーザーに頼む
- **通信の中身（get_network_request の本文）を読まない**。とくに `/api/phone-link` と `/api/settings` の応答には、合言葉とパスワードが入る。list_network_requests で状態の番号（200、422 など）を見るのはよい
- 写しを撮るのは、パスワードの欄が伏せ字（●）のままの画面だけ。写しはこのフォルダに `V-番号-説明.png` で残す
- **管理ページを開くたび、操作のたびに `list_console_messages` でコンソールの誤り（error）を見て、あれば記録する**（前回は、JS が途中で止まって画面が空になる不具合があった）

## 始める前に

1. **chrome-devtools-mcp が使えるか**を確かめる（`list_pages`）。使えなければ、ユーザーに伝えて、前の版の手順（管理ページもユーザーが操作する）で進めるか聞く
2. ユーザーに本体を終了してもらう。あなたが、本体のフォルダの `config.yaml` を `config.yaml.before-s2-33b` という名前で写す（中身は表示しない）
3. ユーザーに、このフォルダ（`s2-33b`）の `irl-live-keeper.exe`（20:35 に作ったもの）を、本体のフォルダの exe と入れ替えてもらう。本体と OBS を起動してもらう
4. あなたが devtools で `http://127.0.0.1:<admin.port>/` を開く（`new_page`）。ログインの画面が出たら、**ユーザーに、devtools が開いた Chrome の窓でパスワードを入れてログインしてもらう**（あなたは入れない）。ログインしたら、コンソールの誤りを見る
5. **OBS のメディアソースの読み取りパスワードがずれている**（前回の T-11 のあと、config.yaml を元に戻したため）。送信の設定の画面は読み取らずに、`evaluate_script` で部品を押す: `document.querySelector('[data-page="sender"]').click()` → `document.querySelector('[data-regenerate="read"]').click()`（「読み取りパスワードを作り直す」）→ 確認の窓が開いたら、そこだけ `take_snapshot` して「OBS のメディアソースも書き換える」（`#settings-update`）にチェックを入れ、「反映する」（`#settings-accept`）を押す。うまくいかなければ、ユーザーに手で操作してもらう。カメラの映像が OBS に戻ることをユーザーに見てもらう

## 片づけ

- あなたが起動した `occupy-ports.ps1` を PID で止める。devtools で開いたページを閉じる
- 設定を `config.yaml.before-s2-33b` に戻すかはユーザーに聞く。**戻す場合は、読み取りパスワードが「始める前に」の 5 より前のものになるので、OBS のメディアソースとずれる**ことを伝える（戻すなら、戻したあとに本体を起動し直し、もう一度「送信の設定」の「読み取りパスワードを作り直す」を「OBS のメディアソースも書き換える」つきで行う）
- 本体は、ユーザーの判断で動かしたままにするか、終了してもらう
