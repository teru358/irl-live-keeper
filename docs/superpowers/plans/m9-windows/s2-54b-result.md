## 気になった文言と見た目

1. **`{camera.kbps:0}` が空になる（Y-15）。** 今のシーンのカメラが0台か2台以上のとき、`camera.*` は未定義なので、`:0` の書式を付けても空になる。指示書の例のテンプレートでは「 kbps カメラなし」になり、「kbps」だけが先頭に残る。案内の例は `{if camera.id}{camera.name} {camera.kbps:0} kbps{else}カメラなし{end}` のような形がよい（`{else}` が使えるかは見ていない）
2. **配信開始の知らせが残り続ける。** 「配信が始まったため、OBS へのテスト反映を解除しました。」が、配信を止め、「OK」「LOW」「オフ」を操作したあとも、一覧の下に出ている。約8分後（20:55）の片づけの時点でも残っていた
3. **一覧でもプレビューの問い合わせが毎秒続く。** 一覧を開いている間、`/api/sources/preview`（POST）がおよそ1秒ごとに続く。見た目のちらつきはなくなったが、スマホで開きっぱなしにすると通信が続く
4. **「設定」の画面の SELECT 2つに id も name もない。** 「シーン」と「待機シーン」。コンソールに `[issue] A form field element should have an id or name attribute (count: 2)` が出る
5. **ページを読み込み直すと、「回線の状況のテスト」が「実際」に戻る。** emulate で読み込み直したとき、「OK」から「実際」に戻った（そのとき「OBS にも反映」はオフ）。決めのとおりならよい

## 指示書の誤り

1. **Y-5: 差し込む前の CSS が空で、確かめにならない。** 指示書の流れでは「回線の表示」の自由な CSS が空なので、「先頭」と「終わり」の区別がつかない。今回は先に `/* s2-54b */` を入れて保存し、開き直してから差し込んだ。指示書の手順に「先に CSS へ1行入れて保存する」を足すとよい
2. **Y-12: `resize_page` では 390 にできない。** Chrome の窓は幅 500 より小さくならなかった（innerWidth 500）。emulate（390x844x3,mobile,touch）を使った。emulate を付け外しすると、ページが読み込み直される
3. **Y-15 と Y-8 の順番。** 指示書の順では、Y-8 の `test restore` で試験のシーン（T-A など）が消えてから Y-15 をする。その場合、「2台が映るシーン」が通常のシーンコレクションにない（Camera、Camera2、Standby、Talk のどれも1台か0台）。今回は restore の前に Y-15 を行い、T-B、T-Sub、T-A、⚠回線待機中 を使った。指示書で「Y-15 は Y-8 の restore の前に、試験のシーンで行う」と書くとよい
4. **Y-15 の例のテンプレート。** 「カメラなし」のシーンで「 kbps カメラなし」となり、意図した見た目にならない（気になる点の1）
5. **Y-6 の最初の値。** OBS に足した直後の値は 0（実際の値）で、管理ページのプレビュー（「OK」で 4200）とは違う。「OBS にも反映」がオフだからで正しいが、指示書に書いておくと迷わない
6. **Y-14 の番号。** 表では Y-15 のあとに Y-14（片づけ）が来ていて、番号と順番がずれている
7. **Y-9 の条件。** 「Y-8 をしないときは」とあるが、Y-8 をしてもすぐにできて、`test obs disabled` は Y-8 だけでは確かめられない。Y-8 のあとにも行うと書くとよい
