## 気になった文言と見た目

1. **`camera.hidden` の意味「本体が隠している項目の数」が分かりにくい。** 何を隠しているのか（カメラのソースを、回線が悪いときに隠しているもの）が書かれていない。「回線が悪いあいだ、本体が隠しているこのカメラのソースの数」のように書くとよいと思う。ログでは `camera hidden camera=sub items=3` と出ているので、それと合う言い方にするとよい
2. **送っていないときの `camera.<id>.protocol` の値が空。** ほかの未定義の値は「—」なのに、ここだけ何も出ない（`camera.main.protocol` と `camera.sub.protocol`）。空の文字列が入っているのか、未定義なのかが分からない
3. **OBS につながっているのに `obs.fps` と `obs.render_skipped` が「—」。** 配信していないときは取らない作りなら、意味の文に「配信中だけ」と書くとよい
4. **`camera.state_for` などの時間の書き方が分からない。** 今の値は「0:02:56」と出るが、意味の文には書き方が書かれていない。`standby.for` と `stream.elapsed` も同じ
5. **カメラごとの区分に `camera.<id>.id` がない。** id が見出しにあるので要らないとも言えるが、「今のシーンのカメラ」の行と数が合わない（11 と 10）。わざとそうしているなら問題ない
6. **一覧の値とプレビューが、1回分ずれることがある。** 同じときに読んで、一覧が 1902、プレビューが 2087 だったことが2回あった。どちらも1秒ごとに変わるが、取ってくるときが別のようだ
7. **「直しが要る」の理由に、どの名前が知らないのかが書かれていない。** 「1 行 5 文字目: 知らない値の名前です」だけで、`link.kbps` が知らない名前だとは書かれていない。名前を書くか、新しい名前（`camera.kbps`）を案内するとよい。エディターの赤い下線も、名前全体ではなく先頭の「l」の1文字だけに付く
8. **「値の一覧」は、開き直すとたたまれた状態に戻る。** 一覧へ戻って「編集」を開くと、毎回たたまれている。よく使うなら、開いた状態を覚えておくとよいと思う
9. **テストの値の `obs.scene` は、実際のシーンではなく「Camera」になる。** 「OK」と「DOWN」は監視対象のシーン、「自動の待機中」は待機シーンになるので作りどおりと思うが、画面にそう書かれていないので、実際のシーンと取り違えやすい
10. **起動のたびに 0 バイトの crash ログができる（前回から変わらない）。** 今回は `crash-20261127-221117.log` と `crash-20261127-222852.log` ができた。前のものは、次の起動のときに消えるようだ（今は 222852 だけが残っている）

## 指示書の誤り

1. **Z-7 の「YAML として正しいかを確かめる」は、この PC ではできない。** Python は入っておらず（Store の案内が出るだけ）、Node にも YAML の部品がない。字下げとキーの並びを見て、本体が読めることで確かめた。確かめ方を指示書に書いておくとよい（たとえば「本体が起動して、ほかのソースが出れば正しい」）
