# S2-88 S2-82 の直しと素材の日本語の名前の実機の確かめ（chrome-devtools-mcp を使う。Windows の Claude Code 向けの指示書）

前回（`../s2-82/s2-82-agent-brief.md` と `s2-82-result.md`）の続き。ユーザーへの文は日本語。手順は画面に出る名前で書いてある（「」の中が画面の文字）。前提の状態は決めつけず、今の値を見てから進める。devtools のツールは `pageId` が要る。

## devtools で守ること（前回と同じ）

- パスワードと、URL のパスワードの部分を書かない。config.yaml を直接書き換えない
- 「表示」（目玉のアイコン）を押さない。通信の中身（応答の本文）を読まない
- **カメラのカードの「送り先」を開いた状態では、写しも読み取り（take_snapshot、本文の読み取り）もしない**（URL とパスワードが文字で出る）。送り先はユーザーに見てもらう
- **LAN の番地は記録しない**。写しを撮る前に、番地が出ている欄（「送り先の住所」、ソースの「別の PC の OBS 用」）の文字を「<LAN の番地>」に置き換える
- 操作のたびにコンソールの誤りを見る。止めてよいのは自分が起動したものだけ（PID で）

## この版で変わったこと（spec v0.33）

- 再起動して反映のあと、画面の左上に英語の「Failed to fetch」が残る不具合を直した。再起動の間は本体を読みに行かず、つながり直したら設定と送り先を読み直す
- 通信の失敗は「本体につながっていません」と日本語で出し、つながり直すと消える。知らせは、ページを移る・次の操作をする・元の状態が終わる、で消える
- 「保存」は、変更がなければ確かめの窓を開かず「変更はありません。」と出す
- **「直前の保存を取り消す」はなくした**（「カメラ」にも「設定」にもない）。「本体を再起動する」は残る
- `<style>` の中の規則の外（`}` のあとなど）へ画像を落とすと、`.image { background: url("…") no-repeat; }` の形で入る。宣言の中（`{` と `}` の間）なら今どおり `url("…")` だけ
- 「状態」の各カメラのボタンは「送り先」の名前になり、押すと「カメラ」のそのカメラのカードへ移る
- **素材の名前に日本語を使える**（漢字・かな・全角の英数字など）。使えない記号や空白は `_` に替わる。本文には `<img src="/source/files/夕焼け.png">` のように日本語のまま書く
- 素材の名前は**大文字小文字まで完全に同じときだけ**使う。`Sunset.png` があっても、本文の `sunset.png` は「素材が見つかりません」になる

このフォルダの中身: `irl-live-keeper.exe`（本体）、`ctl.exe`、`dest.yml`（試験の配信先）、**試験用の画像 `夕焼け.png`（橙の四角）と `青空.png`（青の四角）**。ドロップにはこの2つを使う（手元の写しは画面が写り込むので使わない）。

## 始める前に

1. `list_pages` で devtools が使えるか確かめる
2. ユーザーに本体と OBS を終了してもらう。あなたが `config.yaml` を `config.yaml.before-s2-88` に、`sources.yaml` を `sources.yaml.before-s2-88` に写す（中身は表示しない）。今回は config.yaml の手直しは要らない（前回の形のまま読める）
3. このフォルダの `irl-live-keeper.exe` を本体のフォルダの exe と入れ替えてもらう（ハッシュで同じことを確かめる）。`ctl.exe` もこのフォルダのものを使う
4. 本体と OBS を起動してもらう。devtools で管理ページを開き、ログインの画面が出たらユーザーにログインしてもらう
