# S2-95 UI/UX と文言の直しの実機の確かめ（chrome-devtools-mcp を使う。Windows の Claude Code 向けの指示書）

前回（`../s2-88/s2-88-agent-brief.md` と `s2-88-result.md`）の続きです。

- ユーザーへの文は日本語で書く。
- 手順は画面に出る名前で書いてある（「」の中が画面の文字）。
- 前提の状態は決めつけず、今の値を見てから進める。
- devtools のツールは `pageId` が要る。

## devtools で守ること（前回と同じ）

- パスワードと、URL のパスワードの部分を書かない。
- config.yaml を直接書き換えない。
- 「表示」（目玉のアイコン）を押さない。
- 通信の中身（応答の本文）を読まない。
- **カメラのカードの「送り先」を開いた状態では、写しも読み取り（take_snapshot、本文の読み取り）もしない**（URL とパスワードが文字で出る）。
- **LAN の番地は記録しない**。写しを撮る前に、番地が出ている欄の文字を「<LAN の番地>」に置き換える。対象の欄は次の3つ。
  - カメラの「送り先のアドレス」
  - ソースの「別の PC の OBS 用」
  - 「スマホで開く」の窓
- 操作のたびにコンソールの誤りを見る。
- 止めてよいのは、自分が起動したものだけ（PID で止める）。`Stop-Process -Name` のような名前での停止はしない。
- 設定を保存するのは、この指示書に書いた所だけにする。確認の窓は、書いていない所では「いいえ」で閉じる。

## この版で変わったこと（spec v0.37。2026-11-28 のユーザーの決め）

- **確認の窓**: ブラウザの確認の窓はなくなり、すべて画面の窓になった。
  - 題は「〜しますか？」、ボタンは「はい」「いいえ」。何が起きるかは題の下に書いてある。
  - 終わらせる・消す操作（配信終了、削除、捨てる、配信中に配信が切れる再起動・保存・作り直し）では、「はい」が赤で、開いたときのフォーカスが「いいえ」にある。
  - ほかの操作では「はい」が青。Escape は「いいえ」と同じ。
- **配信のボタン**: 状態の画面の「配信」の節にある、1つのボタンになった。
  - 配信していないときは青の「配信開始」、配信中は赤の「配信終了」。
  - 確認は「配信を開始しますか？」「配信を終了しますか？」。
  - OBS とつながっていないときは押せず、「OBS につながっていません」と出る。
- **言葉**: 「本体」「確認」「捨てる」「切替」「アドレス」にそろえた。
  - 設定の区分「送信」は「OBS の読み取り」になった。
  - ボタンは「保存する」「削除する」「編集する」「コピーする」の形。カメラを足すのは「追加」のまま。
  - 注記は「＊ 保存すると本体が再起動します」（1ページに1回）。
- **カメラの削除**: 「削除する」（赤）を押してもカードは消えず、「保存すると削除します」と「取り消す」が出る。
- **スマホの幅のメニュー**: 今の画面に印（太字と左の線）が付く。開くとボタンが「閉じる」になる。Escape で閉じる。
- **ページの URL**: 末尾に `#status`・`#cameras`・`#sources`・`#settings` が付く。読み直しても同じページに残り、ブラウザの「戻る」でも戻れる。
- **押す所**: どれも高さ 44px 以上になった。押せないスイッチは薄く見え、理由が下に出る。
- **見た目**
  - 下書きがあると、画面の下に「保存していない変更があります　保存する　読み直す」の帯が貼り付く。
  - 「本体を再起動する」は、線で区切った下にある。
  - 状態の各カメラの「送り先 ›」は、名前の行の右にある字のリンクになった。
  - 「注意」の見出しは、注意があるときだけ出る。
  - 「隠したカメラの映像をすべて戻す」は「カメラの表示」の節にある。
  - ダークのとき、ソースのプレビューの地が白くならない（透けを示す市松が見える）。
- **誤りの文**
  - パスワードが違うときは「パスワードが違います。」。
  - MediaMTX の状態は日本語（「動いている」「止まっている」など）。
  - ソースの「URL 用の名前」が空のときや使えない文字のときは、理由ごとの文になる。

このフォルダの中身は次の3つ。

- `irl-live-keeper.exe`（本体）
- `ctl.exe`
- `dest.yml`（試験の配信先）

## 始める前に

1. `list_pages` で devtools が使えるか確かめる。
2. ユーザーに本体と OBS を終了してもらう。
3. あなたが次の2つを写す（中身は表示しない）。今回は config.yaml の手直しは要らない。
   - `config.yaml` → `config.yaml.before-s2-95`
   - `sources.yaml` → `sources.yaml.before-s2-95`
4. このフォルダの `irl-live-keeper.exe` を、本体のフォルダの exe と入れ替えてもらう（ハッシュで同じことを確かめる）。`ctl.exe` も、このフォルダのものを使う。
5. 本体と OBS を起動してもらう。
6. devtools で管理ページを開き、ログインの画面が出たら、ユーザーにログインしてもらう。
7. **`ctl.exe` の環境変数**（コマンドごとに新しいシェルになるなら、毎回付ける）:
   - `$env:OBS_WS_ADDR = "127.0.0.1:4455"`
   - `$env:OBS_WS_PASSWORD_FILE = (Resolve-Path <本体のフォルダ>\ws-password.txt).Path`
   - ファイルの中身は表示しない。ファイルの場所は、前回の結果の記録で確かめる。

## 試験の配信先（H-2・H-3 で使う。ユーザーの許しを得てから）

1. このフォルダで `mediamtx.exe .\dest.yml` を起動し、PID を記録する。`mediamtx.exe` は本体のフォルダのものを使う。
2. `ctl.exe test setup` を実行し、`ctl.exe profile` が `IRLKeeper-Test` になったことを確かめる。
3. 使い終わったら、次の順で戻す。
   - OBS の配信が止まっていることを確かめる。
   - 試験の配信先を PID で止める。
   - `ctl.exe test restore` を実行し、`ctl.exe profile` が元に戻ったことを確かめる。
