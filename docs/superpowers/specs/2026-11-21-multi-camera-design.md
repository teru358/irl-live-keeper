# irl-live-keeper 設計 — 複数のカメラ（第2段階 区切り0）

- 作成日: 2026-11-21
- 版: v0.1（変更は末尾の変更履歴を参照）
- 状態: 2026-11-21 の brainstorming でユーザーが節ごとに承認した内容を文書化したもの
- 前提: コアの spec `docs/superpowers/specs/2026-11-18-core-design.md`（v2.15。以下「コアの spec」）と第2段階の spec `docs/superpowers/specs/2026-11-20-stage2-design.md`（v0.6。以下「第2段階の spec」）。この文書は両者の一部を置き換える（第8節の表）。食い違うときはこの文書を優先する

## 1. 目的と範囲

ユーザーの用途（2026-11-21 の言葉）: 「メインカメラとサブカメラをそれぞれのソースへ転送。ひとシーンにカメラソースを2本取り込む。手元カメラを適宜使用して、カメラシーンを切り替えて使う」。

- 送信の入力（カメラ）を1〜8本にする。カメラごとに MediaMTX の path、回線の判定、OBS のメディアソースを持つ
- カメラごとに、回線が悪いときの動きを択一で選ぶ: 待機シーンへ送る（`standby`）か、そのカメラのソースを OBS で隠す（`hide`）
- どのシーンにどのカメラが映るかは、本体が OBS から自動で調べる（`obs.monitored_scenes` と `obs.media_source` は廃止）
- RTMP と SRT の受付を個別に止められるようにする
- 第2段階の頭（区切り0）に置く。第2段階の残りの部品（記録、グラフ、ソース、管理ページ）は、初めからカメラごとの形で作る（第7節）

作り方は、今の switcher を広げて、シーンの切替と「隠す」を1つの状態機械で判断する形にする（2026-11-21 のユーザーの裁定。2つの状態機械に分ける形は、全部隠れたら待機へ、戻る順序、承認の世代、人の操作の見分け、切替中の抑止が、機械の間の取り決めになり、テストの表で網羅しにくいため選ばなかった）。待機の持ち主と戻り先、期待の照合と期限、実行の直前の承認、目的ごとの有効条件、実行役とのチャネルの決まりは今のまま使う。

入れないもの: カメラごとの資格情報（ユーザーは1人で使う想定。資格情報は全カメラで共通）、カメラごとの「何もしない」（全体の `switch.auto_enabled: false` で足りる）、悪いカメラの代わりに別のシーンへ送る形。

## 2. 設定

```yaml
cameras:                    # 1〜8台。上から順に表示する
  - id: main                # URL の path。英小文字・数字・- _ の 1〜32 文字（先頭は英小文字か数字）。重複不可
    name: メインカメラ       # 表示名（日本語可）。1〜32 文字
    on_bad: standby         # 回線が悪いとき: standby（待機シーンへ送る）/ hide（このカメラのソースを OBS で隠す）
  - id: sub
    name: サブカメラ
    on_bad: hide
    switch:                 # 省略可。書いた項目だけ、共通の switch の値を上書きする
      fail_kbps: 400
      recover_kbps: 800

mediamtx:
  rtmp_enabled: true        # RTMP の受付。RTMP と SRT のどちらかは true にする
  srt_enabled: true         # SRT の受付。RTSP は OBS の読み出しに使うので止めない
```

- 初回に作る config.yaml のカメラは `main`（表示名「メインカメラ」、`on_bad: standby`）の1台。これで第1段階と同じ動きになる
- **なくなる設定**: `stream.name`（カメラの `id` に置き換え）、`obs.media_source`、`obs.monitored_scenes`（第3節で OBS から調べる）。まだ配布していないので古い形は読まない。残っていたら知らない項目として不正にし、理由に書き直し方を添える（`admin.listen` と同じ扱い。コアの spec 4章）
- **検証**（コアの spec 4章に足す）:
  - `cameras` は1〜8台。`id` は `^[a-z0-9][a-z0-9_-]{0,31}$` で、重複しない。`all` と `all_others` は使えない（MediaMTX の path の設定で特別な名前のため）
  - `name` は1〜32文字（Unicode の文字数）で、制御文字を含まない。重複してよい
  - `on_bad` は `standby` か `hide`
  - `switch` の上書きは、共通の値と合わせたあとの5つの値で、共通の閾値と同じ規則（`recover_kbps` > `fail_kbps`、秒は1以上、`down_sec` ≤ `low_sec`）を確かめる。理由の項目名は `cameras[<番号>].switch.<項目>`（番号は0から）。`switch` の下に知らない項目があれば不正
  - `rtmp_enabled` と `srt_enabled` の両方が false なら不正
- **反映の区分**（第2段階の spec 7章の表に足す）: すぐ反映は、カメラの `name`、`on_bad`、`switch` の上書き。再起動して反映は、カメラの追加・削除・並べ替え・`id` の変更と、`rtmp_enabled`・`srt_enabled`（MediaMTX の path と受付が変わるため）
- **URL**: カメラごとに作る。資格情報は全カメラで共通（`stream.publish_user` などはそのまま）
  - SRT: `srt://<host>:<srt_port>?streamid=publish:<id>:<user>:<pass>`（`srt_enabled` が false なら作らない）
  - RTMP: `rtmp://<host>:<rtmp_port>/<id>?user=<user>&pass=<pass>`（`rtmp_enabled` が false なら作らない）
  - OBS 用: `rtsp://<read_user>:<read_pass>@<obs_read_host>:<rtsp_port>/<id>`
- **mediamtx.yml**（コアの spec 8章を置き換える部分）: path はカメラの `id` の数だけ書き、それ以外は受け付けない。`rtmp: no`、`srt: no` を `*_enabled` に合わせて書く。ポートの事前確認は、止めたプロトコルのポートを確かめない
- **ID を変えたとき**: 送信用 URL と OBS 用 URL が変わる。スマホのアプリは手で直す。OBS のメディアソースは、第2段階の spec 7章「OBS のメディアソースの URL の書き換え」をカメラごとに使える（区切り2）

## 3. シーンの地図

本体は OBS から**シーンの地図**を作る: カメラごとのメディアソース、シーンごとの項目、どのシーンにどのカメラが映るか。

### カメラのメディアソース

- `GetInputList`（`inputKind: ffmpeg_source`）で入力を集め、それぞれの `GetInputSettings` の `input`（URL）を読む。`is_local_file` が true のものは除く
- URL を解析し、スキームが `rtsp`、ポートが `mediamtx.rtsp_port`、path（先頭の `/` を除き、末尾の `/` を除いたもの）がカメラの `id` と同じなら、その入力をそのカメラのソースとする。host と資格情報は見ない（`127.0.0.1` と中継 PC の LAN のアドレスのどちらでもよいため）。URL はログに書かない（資格情報を含む）
- 1台のカメラを複数のメディアソースで読んでいてよい。どのメディアソースにも当たらないカメラは status の `warnings` に出す（「<表示名> のメディアソースが OBS に見つかりません」）。メディアソース以外の種類（VLC ビデオソースなど）は調べない

### シーンの項目と「映る」

- `GetSceneList` の各シーンの `GetSceneItemList` を読む。項目がシーン（入れ子のシーン）なら、そのシーンの項目を、グループ（`isGroup`）なら `GetGroupSceneItemList` を、中までたどる（同じシーンを2回たどらない。循環しない）
- 地図の項目は、シーン（またはグループ）の名前、項目の ID、ソースの名前、表示か非表示か、を持つ
- **カメラの項目**: ソースの名前がカメラのメディアソースである項目
- **シーン S にカメラ c が映る**: S から c の項目まで、たどる途中の項目（入れ子のシーンやグループの項目と、c の項目そのもの）がすべて「表示」であること。ただし、本体が隠した項目（第5節の一覧にあるもの）は表示として数える（隠したことでそのシーンのカメラから外れないため）。人が手で非表示にした項目は数えない
- **分類**（コアの spec 6章「シーンの設定と分類」を置き換える）: 待機シーンは今どおり `obs.standby_scene` の名前で決める（カメラが映っていても待機シーン）。監視対象（Monitored）は、待機シーンでなく、カメラが1つ以上映るシーン。管理外（Other）は、カメラが映らないシーン

### 新しく保つ

- OBS につながったとき（`OBSConnected` を流す前ではなく、流したあと）に全部を読み、`SceneMapChanged{Map}` を流す。地図ができるまでは、今のシーンのカメラを「不明」とし、自動の切替、隠す、戻すをしない（手動の操作と配信開始時の切替は今どおり）
- 次のイベントを受けたら、0.3秒まとめてから全部を読み直す: `SceneCreated`、`SceneRemoved`、`SceneNameChanged`、`SceneItemCreated`、`SceneItemRemoved`、`InputCreated`、`InputRemoved`、`InputNameChanged`、`InputSettingsChanged`。読み直しの間に次のイベントが来たら、終わったあとにもう一度読む
- `SceneItemEnableStateChanged` は読み直さず、`ItemEnabledChanged{Scene, ItemID, Enabled}` として流し、switcher が地図を直接書き換える（第5節の期待の照合にも使う）
- **読み直しと表示の変化の順**: 読み直しは補助の接続で行うので、結果が届くまでに本来の接続から `ItemEnabledChanged` が届くことがある。core は、読み直しを始めてから結果が届くまでに受けた `ItemEnabledChanged` を覚えておき、`SceneMapChanged` を渡したあとに、同じ順で渡し直す（新しい表示の状態を古い読み取りで上書きしないため）
- 読み直しは**補助の接続**（第2段階の spec 6章）で行う。自動切替の `SetScene` を待たせないため。補助の接続は、本来の接続が OBS につながっている間は常に開いておく（第2段階の spec 6章「開く条件」を置き換える。試す間隔と期限の規則はそのまま）。補助の接続が開けない間は、最後にできた地図を使い続け、status に警告を出す。接続のあと一度も地図ができていなければ、上の「不明」のまま
- 読み取りの途中で失敗したら（期限切れ、シーンが消えた、など）、その回の結果は捨て、1秒あけて読み直す

## 4. 回線の判定とシーンの健康

### カメラごとの判定

- Poller は1秒に1回、`GET /v3/paths/list` を1回読み、カメラごとの Sample（同じ `At`）を作る。各 path の値の扱い（基準、publisher の識別子、`online`、`inboundBytes`）はコアの spec 5章の1本の path と同じで、カメラごとに基準を持つ。`/v3/srt/conns/list` は、SRT のカメラがあるときだけ1回読み、path ごとに振り分ける。API が失敗したら、全カメラの Sample に `Err` を入れる
- Judge はカメラごとに1つ。閾値は共通の `switch` にカメラの上書きを合わせたもの。規則（OK / LOW / DOWN、続いた秒数の数え方、起動直後は DOWN）はコアの spec 5章のまま
- 送っていないカメラは、今と同じく 0 kbps で、`down_sec` で DOWN になる

### シーンの健康

監視対象のシーン S の健康（OK / LOW / DOWN）を、そのときの地図とカメラの判定から計算する純粋な関数で決める。

- S に映るカメラ（第3節）のうち `on_bad: standby` のものが1つでも OK でなければ、**悪い**
- S に映るカメラがすべて `on_bad: hide` で、すべて OK でなければ（全部隠れる）、**悪い**
- それ以外は **OK**（「待機へ送る」カメラがすべて OK で、「隠す」カメラの一部が悪いときは、隠すだけでシーンは OK）
- 悪いときの LOW と DOWN は、悪いと判断したカメラ（上の2つの条件に入ったもの）のうち、いちばん悪いもの（DOWN > LOW）
- 待機シーン、管理外のシーン、地図にないシーンには健康がない。健康には独自の待ち時間を足さない（カメラごとの判定の秒数で足りる）

## 5. switcher の変更

### 入口と出力

- `LinkChanged{State}` を **`CameraChanged{Camera, State}`** に置き換える
- **`SceneMapChanged{Map}`** と **`ItemEnabledChanged{Scene, ItemID, Enabled}`** を足す
- `ScenesConfigured` から `Monitored` を外し、カメラの一覧（`id`、`on_bad`）を足す。`ConfigEpoch` を進める条件は、今の内容にカメラの一覧を足したもの
- Action に **`SetItemEnabled{Scene, ItemID, Enabled}`** を足す。`RestartMedia` は **`RestartMedia{Inputs []string, Wait}`**（並べた入力に順に RESTART を送り、最後に1回だけ待つ）にする
- `Machine.Handle` は **バッチの列**（0個以上、出した順）を返す形にする。1つの入口から、シーンの切替と隠すバッチが同時に決まることがあるため。列の中の順は、シーンの切替が先、隠す・戻すが後（全部隠れるときは、先に待機へ送ってから隠す。空いた画面を映さないため）

### 目的と有効条件

コアの spec 6章の表を次のように変える（書いていない目的は変えない。共通の条件〔接続、`ConnEpoch`、`StreamEpoch`〕は今のまま）。

| 目的 | バッチ | 有効条件（変えるところ） |
|---|---|---|
| AutoFail | `[SetScene(待機シーン)]` | 今のシーンが監視対象で、**健康が悪い**（「受信状態が LOW / DOWN」を置き換え） |
| AutoRecover | `[RestartMedia(戻り先に映る on_bad: standby のカメラのソースすべて), SetScene(戻り先)]` | **戻り先の健康が OK**（「受信状態が OK」を置き換え）。加えて、戻り先に映るカメラの ShowCamera が未完了でない |
| StandbyOffMonitored | `[RestartMedia(同上), SetScene(戻り先)]` | `auto_enabled` が true なら**戻り先の健康が OK**。悪いときの `Replace`（持ち主を `auto` にする）は今のまま |
| HideCamera(c) | `[SetItemEnabled(項目, false) …]`（c の項目のうち、今表示のものすべて。全シーン） | 配信中、`auto_enabled`、c が `on_bad: hide`、c が OK でない、地図ができている、c が「人が戻した」印を持たない |
| ShowCamera(c) | `[RestartMedia(c のソースすべて), SetItemEnabled(項目, true) …]`（本体が隠した c の項目すべて） | c の一覧が空でなく、c が OK（または下の「無条件に戻すとき」） |

- 戻り先の健康は、承認のときに、その時点の地図と判定で計算し直す。地図が変わっても新しい世代の番号は足さない
- AutoRecover の RESTART は「待機へ送る」カメラだけにする。「隠す」カメラは、OK に戻った時点の ShowCamera が RESTART してから表示に戻すので、AutoRecover は戻り先のカメラの ShowCamera が終わるまで待つ（上の有効条件。終われば次の判断で出る）。これで、戻り先で隠していたカメラが表示に戻ってから、戻り先へ切り替わる
- HideCamera と ShowCamera は、シーンの切替ではないので、`SceneEpoch`、`ConfigEpoch`、切替中の抑止を掛けない。同じカメラの HideCamera と ShowCamera は、どちらかが未完了の間はもう一方を出さない（今の「同じ目的の未完了のバッチがある間は出さない」を、カメラごとに HideCamera と ShowCamera をまとめて当てはめる）
- `SetItemEnabled` の承認で、地図の上でその項目がすでに目的の状態なら `Skip`。地図にない項目（消された）なら `Skip`
- 失敗と再送: HideCamera と ShowCamera は、Auto と同じく、失敗や期限切れのあと、条件が続く間 `Tick` で出し直す（コアの spec 6章「再送の歯止め」と同じ間隔と上限）。`last_error` には、上限に達したときだけ記録する

### 判断し直すとき

コアの spec 6章の「同じ判定をする」入口に、`CameraChanged`、`SceneMapChanged`、`ItemEnabledChanged` を足す。たとえば、人が OBS で、悪い「待機へ送る」カメラを今のシーンに表示させたら、そこで AutoFail になる。

### 戻り先がなくなったとき

「持ち主が `auto` で、戻り先が監視対象でなくなったら、持ち主と戻り先を消す（待機シーンに残る）」（コアの spec 6章）を、`SceneMapChanged` にも当てはめる。戻り先のシーンが OBS で消された、名前が変わった、カメラが映らなくなった、のどれでも同じ。

## 6. 隠す・戻す

### 持つもの

- **隠した項目の一覧**（カメラごと）: シーン（またはグループ）の名前と項目の ID。一覧に入れるのは、`SetItemEnabled(false)` への期待どおりの `ItemEnabledChanged{Enabled: false}` が届いた時点。期待の期限は、応答から2秒（トランジションはないので固定）。期限切れなら一覧に入れない（再送は上の規則）
- **項目の期待**: 本体が送った `SetItemEnabled` ごとに（シーン、項目の ID、目的の状態）を持つ。届いた `ItemEnabledChanged` が期待に当たれば本体の操作、当たらなければ人の操作とみなす
- **人が戻した印**（カメラごと）: 下の「人が途中で触ったとき」

### 人が途中で触ったとき

- 一覧にある項目に、期待にない `ItemEnabledChanged{Enabled: true}` が届いたら（人が OBS で表示に戻した）、その項目を一覧から外し、カメラに「人が戻した」印を付ける。印のある間は HideCamera を出さない（人の判断を優先する）。印は、そのカメラが OK になったときに消す（また悪くなれば、ふつうに隠す）
- 一覧にない項目の変化は、地図を書き換えるだけ

### 無条件に戻すとき

次のときは、カメラが OK でなくても ShowCamera を出す（有効条件の「c が OK」を見ない。共通の条件は見る）。

- 配信が止まったとき（`StreamStateChanged{Streaming: false}`）
- `auto_enabled` が false になったとき
- そのカメラの `on_bad` が `standby` に変わったとき
- 世代を止めるとき（本体の終了と中での再起動。第2段階の spec 7章の止める順の 3 の前に、app が core に「すべて戻す」を頼み、最大2秒待つ。届かなくても止める。下の `hidden.json` が残る）

OBS の接続が切れてつながり直したときは、新しい地図で、一覧の項目のうちまだ非表示のものだけを残す（表示になっていたら外す）。

### `hidden.json`（落ちたときの戻し）

- 置き場所（`--dir`。第2段階の spec 3章）の `state/hidden.json` に、一覧（カメラの `id`、シーンの名前、項目の ID、ソースの名前）を書く。一覧が変わるたびに、一時ファイルに書いてから名前を替える（途中で落ちても壊れないため）。空になったら空の一覧を書く
- 世代を作るとき（第2段階の spec 7章の作る順の 6）に読み、core に渡す。core は、接続のあと最初の地図ができたときに照合する: シーン、項目の ID、ソースの名前が一致し、まだ非表示の項目は、一覧に戻す。そのうえで、配信中で、そのカメラが `on_bad: hide` で OK でなければ隠したままにし、そうでなければ ShowCamera で表示に戻す。一致しないものは捨てる
- 読めない（壊れている）ときは、警告を出して空として扱う

### 記録

- ログ: `camera hidden`（`camera`、`items`、`reason`〔`low` / `down`〕）、`camera shown`（`camera`、`items`、`reason`〔`ok` / `stream_stop` / `auto_off` / `config` / `shutdown` / `restore`〕）、`camera changed`（`camera`、`from`、`to`、`kbps`。今の `link changed` を置き換える）
- できごと（第2段階の spec 8章の一覧に足す）: `camera_hidden`、`camera_shown`（値はログと同じ）

## 7. 第2段階のほかの部分への影響

- **status**（コアの spec 9章、第2段階の spec 6章）: `link` を `cameras`（カメラごとの `id`、`name`、`on_bad`、`state`、`kbps`、`online`、`protocol`、`srt`、`sources`〔メディアソースの名前〕、`hidden`〔隠している項目の数〕、`user_shown`〔人が戻した印〕）に置き換える。`obs` に、今のシーンに映るカメラの `id` の一覧（`scene_cameras`）と、今のシーンの健康（`scene_health`。健康がなければ null）を足す。`urls` はカメラごとにする
- **管理ページ**（第2段階の spec 5章）: 状態の画面の回線の行をカメラごとに。送信の設定の画面をカメラごとの URL と QR に（止めたプロトコルは出さない）。設定の画面に「カメラ」の区分（追加、削除、並べ替え、`id`、表示名、`on_bad`、閾値の上書き〔スイッチで開く〕）
- **小さな窓**（第2段階の spec 4章）: 回線の行をカメラごとに1行（表示名、●、状態、kbps）。カメラの数に合わせて窓の高さを変える
- **グラフ**（第2段階の spec 8章「直近10分」）: カメラごとの線。閾値の横線と色の帯は選んだカメラのもの。待機の印に加えて、隠した・戻した印
- **配信の記録**（第2段階の spec 8章）: `sample` のできごとにカメラの `id` を足し、1秒ごとにカメラの数だけ出す（S2-4。購読の仕組みは変えない）。まとめはカメラごとの平均と最低の kbps、LOW と DOWN の時間と割合、隠した回数と合計の時間。待機の回数・合計・最長は配信全体。CSV はカメラごとの列。meta にカメラの一覧（`id`、`name`、`on_bad`、合わせたあとの閾値）
- **ソース**（第2段階の spec 9章）: 使える値に、カメラごとの値（`camera.<id>.kbps`、`camera.<id>.state`、`camera.<id>.name`、`camera.<id>.hidden` など）と、今のシーンの健康を足す。今の `link.*` は、先頭のカメラの値の別名として残す。回線の状況のテストは、カメラごとに状態を選べるようにする
- **メディアソースの URL の書き換え**（第2段階の spec 7章）: カメラごとに行う。書き換える入力は、第3節で見つけたそのカメラのソース
- **README**: 複数のカメラの使い方（OBS にカメラごとのメディアソースを作る、`on_bad` の選び方）。2台以上を同じ上り回線から送ると帯域を分け合うこと、OBS のメディアソースの「ハードウェアデコードを使用」を勧めること

## 9. テスト

- **config**: `cameras` の検証の表（`id` の形・重複・長さ・特別な名前、`name` の長さと制御文字、`on_bad`、1〜8台、上書きを合わせたあとの閾値の規則と理由の項目名、`switch` の下の知らない項目）、`*_enabled` の両方 false、古い3つの項目のエラーの文、生成した値が検証を通ること
- **URL と mediamtx.yml**: カメラごとの URL、止めたプロトコルの URL と設定とポートの事前確認、path の数
- **シーンの地図**（純粋な関数）: URL の照合の表（スキーム、ポート、path の前後の `/`、host を見ない、資格情報つき、`is_local_file`）。たどり方の表（入れ子のシーン、グループ、途中の非表示、本体が隠した項目を表示として数える、同じカメラを2つのソースで、同じシーンを2回たどらない、循環）。分類
- **健康**（純粋な関数）: 第4節の規則の表（standby が1つ悪い、hide だけ悪い、全部 hide で全部悪い、全部 hide で1つ OK、LOW と DOWN の混ざり、カメラのないシーン、待機シーン）
- **switcher**: 「入口 × 状態」の表を新しく作り、レビューしてから実装する（コアの spec 11章と同じ進め方）。今の列のテストは、カメラ1台・`on_bad: standby`・地図でそのカメラが監視対象のシーンに映る形に置き換えて、同じ結果になることを確かめる（第1段階の動きを壊していない証拠）。加えて: `Handle` のバッチの列の順、隠す・戻すの期待と期限、人が戻した印、無条件に戻すとき、AutoRecover が ShowCamera を待つこと、RESTART の対象、戻り先がなくなったとき、地図の再読み込みの前後
- **core**: 読み直しの間の `ItemEnabledChanged` を渡し直すこと、`hidden.json` の書き直しと次の接続での照合（戻す、引き継ぐ、捨てる、壊れたファイル）、止めるときの「すべて戻す」と2秒の上限
- **ingest**: `/v3/paths/list` の1回の読み取りからカメラごとの Sample を作ること、カメラごとの基準、SRT の振り分け、API の失敗で全カメラに `Err`
- **実機の確認**（ユーザーと一緒に）:
  - Linux（画面なしの OBS）: ffmpeg で2〜3本の偽のカメラを送り、帯域を絞る中継で1本ずつ乱す。待機へ送る・戻る、隠す・戻す、全部隠れて待機へ、戻るときに隠していたカメラが先に表示に戻ること、入れ子のシーンとグループ、人が途中で表示を変える、強制終了のあとの `hidden.json` からの戻し、受付の停止
  - Windows: スマホ2台（できれば別の回線）で同じ流れ。OBS のデコードの負荷（ハードウェアデコードの有無）と、同じ回線から2台を送ったときの乱れ方
