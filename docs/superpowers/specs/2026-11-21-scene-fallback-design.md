# シーンごとの逃がし先（区切り 0c）の設計

- 版: v0.1（変更は末尾の変更履歴を参照）
- 状態: 2026-11-21 にユーザーと節ごとに決めた。0b（隠す・戻す）の実機の確認（M-13 の Windows）のあとに、区切り「0c」として入れる
- もとの設計: カメラの spec `2026-11-21-multi-camera-design.md`（v0.16。以下「カメラの spec」）、コアの spec `2026-11-18-core-design.md` 6章。この文書は、それらの「回線が悪いときは、決まった1つの待機シーンへ送る」を広げる。食い違うときはこの文書を優先する

## 1. 目的

シーンごとに、回線が悪いときの逃がし先を決められるようにする。逃がし先も悪ければ、さらにその逃がし先へ進む。戻るときは、積んだ順を逆にたどる（スタック）。

使い方の例（ユーザーの言葉から）: シーン1にメインカメラとワイプのサブカメラを置く。メインが悪くなったら、サブの全画面のシーン2へ切り替える。サブも悪ければ待機シーンへ。シーン1でサブだけが悪いときは、今までどおりサブを隠す。

## 2. 設定

```yaml
obs:
  standby_scene: Standby       # 共通の逃がし先（今のまま。手動の待機の ON の行き先も兼ねる）
  scene_fallbacks:             # シーンごとの逃がし先（書かないシーンは standby_scene へ）
    - scene: シーン1
      fallback: シーン2
```

- 共通の逃がし先は、今の `obs.standby_scene` のまま（名前を替えると今の config.yaml がすべて書き直しになり、待機シーンには手動の待機の行き先の役目もあるため。ユーザーの裁定）
- `scene_fallbacks` の各行は `scene`（元のシーン）と `fallback`（逃がし先）。名前は、待機シーンと同じく、本体が OBS の地図で名前から引く（config に OBS のシーンの一覧は持たない）
- 3段以上もつなげられる（シーン1 → シーン2 → シーン3 → 待機）
- 検証: 同じ `scene` を2回書く、輪になる（シーン1 → シーン2 → シーン1）、`scene` か `fallback` に待機シーンを書く、空の名前、は不正（`ValidationError`。書き直し方を添える）
- OBS に名前がないとき: 待機シーンの名前がないときと同じく、status の `warnings` に出し、その行を使わない（そのシーンの逃がし先は待機シーン）
- 反映の区分: すぐ反映（積んだスタックは保ち、そのあとの判断から新しい対応を使う）

## 3. 逃がすと戻る（スタック）

**言葉**: シーン S の「逃がし先」は、`scene_fallbacks` に書いたシーン（なければ待機シーン）。逃がし先にも逃がし先があれば、それを順にたどった並びを「S の逃がし先の列」と呼ぶ（例: シーン1 → シーン2 → 待機）。

**逃がす**（今のシーンの健康が悪くなったとき。今の AutoFail を広げる）
- 今のシーンの逃がし先の列を前から見て、**健康が良いシーン**か、待機シーンに着くまで進み、そこへ切り替える。悪い逃がし先は飛ばす
- 今のシーンと、飛ばしたシーンを、スタックに積む。持ち主は `auto`
- 逃がした先でまた悪くなったら、そこから同じように逃がし、スタックに積み足す
- カメラの映らないシーン（たとえば「少々お待ちください」の画像のシーン）も逃がし先にできる。健康がないので、逃がすときは健康を見ずに行き先として使い、そこからは先へ逃げない（待機シーンと同じく列の終わりになる）。スタックのシーンが良くなるのを待って戻る

**戻る**（今の AutoRecover を広げる）
- 持ち主が `auto` の間、スタックのシーンを**いちばん下（最初に逃げた元）から**見て、健康が良いシーンが見つかったら、そこへ戻る。それより上に積んだものは捨てる
- 戻る前に、そのシーンについて次の2つを待つ（空の画面や乱れた映像を映さないため）:
  - 今と同じく、待っている隠した項目（OK のカメラの、本体が隠した項目）が表示に戻ること（カメラの spec 第6節。v0.16 の「実際に表示されているカメラが0なら待つ」も含む）
  - **逆向きの待ち**: そのシーンに、悪い hide のカメラの項目がまだ表示のまま残っていれば、隠れること（隠す要求の途中、隠すのに失敗した、など）
- 戻った先がスタックのいちばん下なら、スタックは空になり、持ち主は `none`

**例**（シーン1 = メイン〔standby〕＋ワイプのサブ〔hide〕、シーン2 = サブの全画面）

| できごと | 今のシーン | スタック |
|---|---|---|
| シーン1でメインが悪くなる | シーン2 | [シーン1] |
| サブも悪くなる | 待機 | [シーン1, シーン2] |
| サブが良くなる（メインはまだ悪い） | シーン2 | [シーン1] |
| メインが良くなる | シーン1 | [ ]（持ち主 `none`） |
| （別の列）待機にいる間に、メインとサブが同時に良くなる | シーン1 | [ ]（シーン2 を飛ばして直接戻る） |
| （別の列）シーン1でメインとサブが同時に悪くなる | 待機 | [シーン1, シーン2]（シーン2 は飛ばす） |
| （別の列）待機にいて [シーン1, シーン2]、メインだけが良くなる（サブは悪い） | シーン1 | [ ]。サブは隠したまま（サブの項目は、悪くなった時点で全部のシーンで隠している） |

**隠すとの関係**: 今までどおり。シーン1でサブだけが悪いときは、サブを隠し、シーンは変えない。シーン2がサブだけのシーンなら、サブが悪ければシーンの健康が悪くなり、逃がす（隠さない）。

## 4. 人の切替、手動の待機、配信の開始と停止

**人の切替**
- 人がシーンを切り替えたら、スタックを全部捨て、持ち主を `none` にする（スタックの中のシーンを選んだときも同じ。人の判断を優先する）
- 人が選んだシーンが監視対象で健康が悪ければ、そのシーンから新しく逃がす（スタックは [選んだシーン] から）
- 人が待機シーンを選んだときは、今と同じく持ち主 `none` のまま残る

**手動の待機**（StandbyOn / StandbyOff）
- ON: 待機シーンへ。持ち主は `manual`。戻り先は**スタックのいちばん下**（元のシーン）。スタックが空なら今のシーン
- OFF: 戻り先の逃がし先の列から、**いちばん元に近い、健康が良いシーン**へ。戻り先がまだ悪く、その逃がし先が良ければそこへ行き、持ち主 `auto`、スタックは [戻り先, …飛ばしたもの]。どれも悪ければ、今と同じく待機に残り、持ち主 `auto` で回復を待つ（`auto_enabled` が false なら、今と同じく待たずに戻り先へ出す）

**配信の開始と停止、つなぎ直し、地図の変化**
- 配信の前は、今と同じく切り替えない（スタックは空）。配信開始時の切替（`on_stream_start`）のあと、そのシーンが悪ければ逃がす
- 配信の停止: 今と同じく持ち主と戻り先を消す。スタックも捨てる。シーンはそのまま
- つなぎ直し: 同じ接続先とコレクションならスタックを保つ。コレクションが変わったら捨てる（カメラの spec の W-04 と同じ）
- 地図の変化: スタックの中のシーンが消えた、または監視対象でなくなったら、そのシーンだけをスタックから外す。空になったら持ち主 `none`（今の「戻り先が監視対象でなくなったら消す」を広げる）

## 5. 0a・0b の規則への影響（M-0c の表で行ごとに決める）

- 0a の「持ち主が `auto` なら今のシーンは待機シーン」という前提が崩れる。0a の表の「整える」手順（W-02 の (2)「持ち主が none 以外なのに今のシーンが待機でなければ消す」）、持ち主と戻り先の規則、シーンの期待の行を、「持ち主が `auto` なら、今のシーンはスタックの上に積んだ逃がし先のどれか」に置き換える
- AutoFail の切替先が待機以外になる。「待機シーンへの切替の期待」「AutoFail の期待が届いたら持ち主を入れる」の行を、逃がし先への切替に広げる
- 0b の「今のシーンを空にしない」「待っている隠した項目」「本体の切替の期待が残る切替先を数える」は、行き先が逃がし先のシーンでも同じに当てる
- status: `standby.return_scene` に加え、スタック（`standby.stack`。シーンの名前の並び）。ログ `scene switch` の `reason` に逃がし先への切替を見分ける値（`fallback`）
- 管理ページと小さな窓の待機の表示（第2段階）は、スタックを読める形にする（S2 の task で）

## 6. テスト

- config: `scene_fallbacks` の検証の表（重なり、輪、待機シーン、空の名前）、ひな形が検証を通ること
- switcher: 0c の「入口 × 状態」の差分の表（0b の表の差分）を作り、Fable か codex sol でレビューしてから実装する。第3節の例の列をすべて列のテストにする。0a・0b のテストは、`scene_fallbacks` が空の設定で、変わらず通ること
- 結合（M-12 の偽の OBS）: 乱数の列に逃がし先の設定を入れ、カメラの spec 第5節の4つと、「逃がした先を空にしない」「戻る先に乱れた hide のカメラの映像を出さない」をいつも確かめる
- 実機: Linux（画面なしの OBS）と Windows（スマホ2台）で第3節の例の列
