### 8章（配信ごとの記録・まとめ・画面）

#### 配信ごとの記録

- **1件の区切り**: OBS の配信の開始から停止まで。開始は `stream`（`streaming: true`）か、記録していないときに受けた `obs_connected`（`streaming: true`）。停止は `stream`（`streaming: false`）
  - history は、記録中に受けた `stream`（true）と `obs_connected`（true）、記録していないときに受けた `stream`（false）と `obs_connected`（false）を、区切りとしては無視する（記録中の `obs_connected` は、できごととして行に残す）
  - 配信中に OBS と切断した場合は記録を続け、`obs_disconnected` を残す。つなぎ直したとき（`obs_connected`）に配信が止まっていたら、`end` の `t` を切断の時刻にして閉じる（`reason: obs_disconnected`）。そのあとに届く `stream`（false）は、記録していないので無視する。切断のあとに書いた sample の行は残るが、集計は `end` の `t` までにする。集計では、sample の区間（`t - iv_ms` から `t`）のうち配信の範囲（開始から `end` の `t`）に重なる部分だけを使う。`end` の `t` より後に書かれた sample でも、区間が `end` の `t` より前に始まっていれば、重なる部分は使う（区間が `end` の `t` より後に始まる sample は使わない）。配信が続いていれば、同じ件を続ける
  - **切断が続くとき**: 配信中の切断が5分続いたら（本体の時計で数える）、`end`（`reason: obs_disconnected`、`t` は切断の時刻）と summary を書いて閉じ、書くのをやめる（OBS を終了したまま本体を動かし続けると、記録中のまま残り続けるため。Machine は切断の間も配信中を保つので、core からは止まったことが分からない）。そのあとつながって配信中なら（`obs_connected`、`streaming: true`）、新しい件にする
  - 本体の終了と中での再起動では、`interrupted` で閉じる（第7節の止める順の5）。起動し直したあと、配信中なら新しい件を始める
- **ファイル**: 配信ごとに1つ、`history/YYYYMMDD-HHMMSS-<乱数4桁の16進>.jsonl`（開始の時刻、ローカル時刻）。`O_EXCL` で新しく作る（同じ名前があれば、乱数を替えて作り直す）。1行に1つの JSON
  - `{id}`（API）は、ファイル名から `.jsonl` を除いたもの。`^[0-9]{8}-[0-9]{6}-[0-9a-f]{4}$` に合うことを確かめてからパスにする（合わなければ 404）
  - 時刻の形: 行の `t` は UNIX ミリ秒の整数。meta の `started_at` は RFC3339
  - 先頭: `{"type":"meta","t":…,"started_at":…,"version":…,"thresholds":{…},"scenes":{…},"standby":{"owner":…,"return_scene":…,"since":…}}`。`t` は開始の時刻（UNIX ミリ秒。集計の範囲の始まり。`started_at` と同じ時刻）。`standby` は開始の時点の待機の状態（持ち主、戻り先、持ち主が `none` でなくなった時刻〔UNIX ミリ秒。`none` なら null〕）
  - 1秒ごと: `{"type":"sample","t":…,"iv_ms":…,"kbps":…,"state":"OK","online":true,"protocol":"srt","rtt_ms":…,"loss":…}`
  - できごと: `{"type":"event","t":…,"kind":"auto_fail","from":…,"to":…,"reason":"low","kbps":…}` など（上の一覧の値）
  - 終わり: `{"type":"end","t":…,"reason":"stopped|obs_disconnected|interrupted"}` を書いてから、`{"type":"summary",…}` を書く
- **書き方**: 1行ずつ追記する。10秒ごとに `fsync` する（落ちても、それまでの行はほぼ残る）
- **`end` のないファイル**（本体が落ちた）: 最後の行の `t` までを集計し（最後のできごとが `obs_disconnected` なら、その時刻まで。下のまとめ）、一覧では「途中で終わった」と示す
- **一覧に出す件**: 書いている途中の件も「記録中」として出す。summary のないファイルは、一覧を作るときに中身から計算し、メモリにだけ覚える（ファイルには書き足さない）
- **保存の日数**: ファイル名の開始の日付で、ログと同じ規則で消す（日付が「今日 − `log.keep_days` 日」より前のもの。コアの spec 10章）。書いている途中のファイルは消さない。起動のときと、日付が変わったときに消す（ログも日付が変わったときに消す。コアの spec 10章を直した）
- **書けないとき**（ディスクがいっぱい、など）: ログに警告を出し、その件の記録を止める。自動切替は止めない。次の配信の開始で、もう一度新しいファイルを作ってみる

#### まとめ

| 項目 | 定義 |
|---|---|
| 集計の範囲 | meta の `t`（開始）から、範囲の終わりまで。範囲の終わりは、`end` の `t`（`end` がなければ最後の行の `t`）。ただし、`end` の `reason` が `interrupted` のときと `end` がないときは、最後のできごと（sample を除く）が `obs_disconnected` なら、その時刻を範囲の終わりにする（切断したまま終わった件に、切断のあとの時間を入れないため） |
| sample の重み | sample は、区間（`t` − `iv_ms` から `t` まで）の受信を表す。重みは、その区間と集計の範囲の重なりの長さ（開始をまたぐ sample と、範囲の終わりをまたぐ sample は、範囲の中の分だけ数える。重なりのない sample は使わない） |
| 欠測 | sample の間が `iv_ms` の2倍より空いたところ（できごとを落とした、など）。隣り合う sample の `t` の差が、あとの sample の `iv_ms` の2倍より大きければ、差から `iv_ms` を引いた時間を欠測とする。範囲の始まりと最初の sample の `t` の差も、同じく最初の sample の `iv_ms` で見る。最後の sample の `t` と範囲の終わりの差が、最後の sample の `iv_ms` の2倍より大きければ、その差を欠測とする。欠測はどの sample の重みにも入らないので、分母と割合の分母から外れる。まとめに欠測の合計を出す |
| 配信の長さ | 範囲の始まりから終わりまで（欠測を含む） |
| つながっている秒（分母） | `online` の sample の重みの合計 |
| 平均のビットレート | `online` の sample の kbps を、重みで加重して平均したもの。`online` の sample がなければ、なし |
| 低いほうのビットレート | 重みが0より大きい `online` の sample の kbps を昇順に並べ、ceil(0.05 × 件数) 番目の値（最も近い順位の方法） |
| LOW と DOWN の時間 | `state` が LOW（DOWN）の sample の重みの合計。割合は、すべての sample の重みの合計に対する比 |
| 自動の待機 | `standby` で `owner` が `auto` になってから、`auto` でなくなるまで。開始の時点ですでに `auto` なら（meta の `standby`）、範囲の始まりから数える（回数にも入れる）。範囲の終わりまで続いたら、範囲の終わりまで。回数、合計の時間、いちばん長い待機 |
| 人の切替の回数 | `user_scene` の数 |
| OBS との切断の回数 | `obs_disconnected` の数 |
| MediaMTX の再起動の回数 | `mediamtx` で `state` が `down` になった回数 |
| 落としたできごと | `dropped` の `n` の合計。0 でなければ、まとめに「一部の値が欠けている」と出す |

- `session.low_count`（第9節）は、この自動の待機の回数と同じ（手動の待機は含めない）

#### 画面

- **一覧**: 日時、長さ、まとめを1行ずつ。新しい順。記録中と、途中で終わった件には印を付ける
- **詳しい画面**: 配信全体のビットレートのグラフ（LOW / DOWN の帯、待機の印）とできごとの一覧。グラフの印とできごとの行を行き来できる。長い配信は、本体が区間ごとに最小・平均・最大にまとめて 2000点ほどに縮めて渡す。拡大は受け取った点の中で行う（拡大した範囲を細かく取り直すことは、2a では作らない。第1節）
- **CSV**: 時刻（ローカル時刻）、kbps、受信状態、プロトコル、RTT（ms）、ロス率、できごと の列

### spec v0.34 の8章（そのまま）

#### 8. できごとと直近10分（見出し）

v0.34（2026-11-28 のユーザーの指示）: 配信の記録（配信ごとのファイル、まとめ、一覧と詳しい画面、CSV、`session.*` の値）は後回しにして、`docs/superpowers/specs/2026-11-28-stream-history-deferred.md` に移した。この章は、できごとの購読、直近10分（メモリ）、「状態」のグラフの元を決める。記録を作るときは、このできごとを受けて作る。

#### できごとの出し方

- core が、ログを書くのと同じ箇所で、できごとを型のある値として出す
- 購読: 受け手ごとに容量つきのチャネルを登録する。core は止まらずに送る（コアの spec 9章のチャネルの決まり）。あふれたら捨てて、その受け手の落とした数を数え、次に送れたときに先に `dropped`（N 件を落とした）を送る
  - まだ送れていない落とした数は、登録ごとの値として、受け手が読めるようにする（core が止まったあとに、受け手が最後に落とした分を知るため）
- Snapshot の更新の知らせも、受け手ごとに登録する形にする（第2節）
- 1秒ごとの値: Poller の SampleSet が届き、Judge に通したあとに、core が `sample` を1件出す（全カメラの値の組。SampleSet の `At` の時刻つき）
- 受け手は、history（直近10分）と web（SSE の `sample` と `event`）
- **購読の形**（v0.4。task 表 S2-4 で決めた）:
  - 登録は `Run` を呼ぶ前だけにする（受け手の history、web の配る役〔世代ごとに1つ。SSE の接続ごとには登録しない〕、S2-31 の app は、世代の作る順の 6 で、core を作ったあと `Run` を始める前に app が登録する。第7節）。`Run` のあとの登録はプログラムの誤りとして panic にする。解除は作らない（受け手は世代と同じ寿命）。中核ループは登録の一覧を鍵なしで読む
  - Snapshot の知らせ: `SubscribeSnapshots()` が容量1のチャネルを返す。中核ループは Snapshot を公開する（`publish`）たびに、満ちていなければ1件送る。受け手は知らせを受けたら `Snapshot()` を読む。登録の前に公開した最初の Snapshot の知らせはないので、受け手は始めに1回 `Snapshot()` を読む
  - できごと: `SubscribeEvents(n)`（n は1以上。容量は受け手が決める。history と web の値は S2-35 と S2-11 で決める）が登録を返す。登録は受けるチャネルと、まだ送れていない落とした数を返すメソッドを持つ。できごとは種類ごとの型（`sample`、`dropped` など。種類の名前を返す `Kind()` と時刻を返す `Time()` の共通の interface を満たす）で、S2-34 で型を足しても購読の形は変わらない
  - できごとの時刻: `sample` は SampleSet の `At`。ほかは、中核ループがそのできごとを出した時刻（`Deps.Now`）。`dropped` は、その `dropped` を作った時刻で、落とした区間の時刻ではない
  - 落とした数は、`Run` が戻ってチャネルを閉じたあと（受け手が閉じたことを見たあと）に読む。動いている間に読んでもよいが、そのときの値は途中の値（atomic で読む）
  - 落とした数があるときの送り方: まず `dropped`（その数）を止まらずに送る。送れたら数を0にし、続けて今のできごとを止まらずに送る。どちらかが送れなかったら、今のできごとを落とした数に足す。例（容量2、受け手が読まない間に e1〜e4 → 受け手が1件読む → e5 → 受け手が2件読む → e6）: 受け手が受けるのは e1、e2、`dropped`(2)、`dropped`(1)、e6 の順（e3、e4 と e5 が落ちた）
  - `Run` が戻るとき（中核ループが止まり、できごとを出さなくなったあと）に、Snapshot の知らせとできごとのチャネルをすべて閉じる。受け手は閉じるまで読む。`Run` を呼ばなかった core のチャネルは閉じないので、作成に失敗した世代では、受け手は閉じるのを待たない

#### できごとの一覧

| 種類 | 出すとき | 値 |
|---|---|---|
| `sample` | SampleSet を受けて Judge に通したとき（1秒ごと。S2-4 で入った） | `t`、`cameras`（設定の順の各カメラ: `id`、`iv_ms`、`kbps`、`state`〔Judge のあとの OK / LOW / DOWN〕、`online`、`protocol`、`rtt_ms`・`loss`・`mbps`〔SRT のときだけ〕、`err`〔path の API が失敗したら true。理由の文は入れない〕） |
| `stream` | 配信状態が変わったとき（ログの `stream state` と同じ箇所） | `streaming` |
| `auto_fail` | AutoFail の切替（ログの `scene switch` と同じ箇所） | `from`、`to`、`reason`（`low` / `down`）、`camera`（悪い代表のカメラの id）、`kbps`（そのカメラの値） |
| `auto_recover` | AutoRecover の切替（同上） | `from`、`to`、`camera`（戻り先に映るカメラのうち最後に OK になったもの）、`kbps` |
| `standby` | ログの `standby changed` と同じ箇所（持ち主、戻り先、戻り先の名前、待機の積み重ねが変わったとき） | `owner`（`none` / `auto` / `manual`）、`return_scene`（シーン名か null） |
| `camera_hidden` / `camera_shown` | カメラのソースを隠す・戻すバッチが終わったとき（ログの `camera hidden` / `camera shown`。カメラごとに1件） | `camera`、`items`（送った項目の数）、`reason`（`low` / `down` / `restore` / `auto_off` / `manual_all` / `config` / `stream_stop` / `shutdown` など、ログと同じ決まった語） |
| `obs_disconnected` | `OBSDisconnected` を受けたとき | なし |
| `obs_connected` | `OBSConnected` を受けたとき | `streaming`、`scene` |
| `mediamtx` | MediaMTX の状態が変わったとき | `state`（`running` / `starting` / `down`） |
| `settings_applied` | 配信中に、すぐ反映を中核ループで差し替えたとき（S2-24 で入った） | 今の設定（シーンの設定と、カメラごとの id・合わせたあとの閾値など。パスワードと URL は入れない）。今は受け手が使わない（配信の記録のためのもの） |
| `dropped` | 受け手のチャネルがあふれたあと | `n`（落とした件数） |

- できごとには、決まった型の値（数値、真偽、決まった語、シーン名、カメラの id）だけを書く。自由な文字列（エラーの文、`last_error` の理由など）は書かない（秘密が混ざる道を作らないため）
- 記録にだけ要るもの（`start_scene`、`user_scene`、`command`、`obs_connected` を `stream` より先に出す順）は、後回しの文書に残した

#### 直近10分

- 配信していないときも含め、`sample` を600件（全カメラの組で）まで、メモリに持つ。できごとも持つ。どちらも10分より古いもの（本体の時計）は落とす（sample が欠けて600件に満たなくても）。世代ごとのもので、中での再起動で空に戻る（カメラの増減は再起動して反映なので、1つの世代の中でカメラの id はそろう）
- `GET /api/history/recent` で返す（形は S2-35 で決める）。そのあとの分は SSE の `sample` と `event`（`sample` 以外のできごと。値は上の一覧と同じ）で届く。画面は、開いたときと SSE をつなぎ直したあとに `recent` を取り直して置き換える（重なりと抜けを `recent` で直す）
- **「状態」のグラフ**（カメラの spec 9節）: カメラごとのビットレートの線（色はカメラの番号で決める）。閾値の横線（`fail_kbps` と `recover_kbps`、カメラごとに合わせたあとの値）と OK / LOW / DOWN の色の帯は、選んだカメラのもの（既定は番号の一番小さいカメラ）。横線は今の値（status）で引き、すぐ反映で変えたら引き直す（過去の区間も今の値の線になる）。帯は sample の `state`（そのときの判定）で塗る。sample が欠けた間は線をつながない。待機に入った・戻った時刻と、カメラのソースを隠した・戻した時刻の縦の印。SRT のカメラは RTT に切り替えて見られる。スマホの幅でも横にはみ出さない
